## 五、踩到的坑（下次直接照做）

### 1. 提前暂存的 `.gitmodules` 会被第一条 commit 吞掉

`11-19` 时 `.gitmodules` 与 gitlink 已处于 staged 状态，于是
`git add flashvla/ ... && git commit` 把这两项一起提交进了「代码」那条，
导致 `chore` 只剩 `.gitignore` 一个文件。

修法（**未推送前**，安全）：

```bash
git reset --soft 3cd30fc && git reset -q     # 回到最初，改动全部回到工作区
# 然后按 C1/C2/C3 重新 add + commit
```

`--soft` 保索引、`git reset` 清索引，工作区文件全程不动。

### 2. `git add third_party/SDN` 报 "adding embedded git repository"

无害。只要 `.gitmodules` 里有该 path，写进索引的就是 `160000 commit`，
用 `git ls-tree HEAD third_party/SDN` 确认即可；`git submodule status` 能正常显示。

### 3. `du -h` 会把子模块报成 59G

`git diff --name-only .. | xargs du -h` 对 `third_party/SDN` 统计的是**工作区目录**，
于是出现「待提交 59G」的假警报。正确做法是统计 **blob**：

```bash
git rev-list --objects origin/main..HEAD \
  | git cat-file --batch-check='%(objecttype) %(objectsize) %(rest)' \
  | awk '$1=="blob"{printf "%8.1f KB  %s\n", $2/1024, $3}' | sort -nr | head
```

### 4. `git ls-tree --stdin` 在这台机器的 git 上输出为空

同样的体积审计不要用 `ls-tree -r -l --stdin`，直接用上面的 `rev-list + cat-file`。

与 11-18 相比只多两条：**子模块改动要先在子模块里提交推送**，**体积审计要用 blob 统计**。

```bash
cd /home/zjr/workspace_tj/StreamingVLA/flashvla

git status

# 2. 暂存（ckpt/logs/runs/results 均已被忽略）
git add -A

# 3. 两道闸门

git diff --cached --name-only | grep -E '\.(safetensors|pt|pth|bin|ckpt|onnx|h5|pkl)$'  # 应空

# 4. 提交 + 推送
git commit -m "改动说明"
git push
```

提交前如需看真实体积，用第五节的 `rev-list | cat-file` 版本，不要用 `du`。
