## 2. P-0（11-18）：机制能不能成立

`1.md` 是全部工作的源头，它先纠正了一个会致命的误解，再给出两条自洽路线。

**核心修正：N 个槽 ≠ N 个候选。**
FlashVLA 的 4 个 buffer 槽是**同一条流水线里 4 个噪声样本的不同成熟度**（跟踪样本 k → k+4 从未被执行的 slot3 滑到 slot0），
不是同一时刻的 4 个备选答案。因此「把 slot1/2/3 补足到 t=0 当候选」在数学上不成立：目标时刻不同、成熟度不等。

**深度 ↔ 宽度换算**（这条是后面所有工作的立论）：

| 方案 | 每次候选数 | suffix token | 串行步数 |
| :--- | ---: | ---: | ---: |
| π0 基线 | 1 | 100 | 10 |
| π0 + SDN (N=12) | 12 | 1200 | 120 |
| FlashVLA 基线 | 1 | 40 | 1 |
| FlashVLA + M=4 流水线 | 4 | 160 | **1** |
| FlashVLA + M=12 流水线 | 12 | 480 | **1** |

> 可引用的一句：**FlashVLA 把 best-of-N 从「延迟×N」变成了「吞吐×N」。**

**两条路线与两阶段改造**：

- 方案 1（单 buffer、只动 slot 0 重噪）：成本低，但多样性受串行深度限制（重噪 m 步才能买 m/N 的多样性），**只能治抖动与接缝，修不了抓空/错物**。
- 方案 2（M 条同步流水线）：串行深度恒为 1、满多样性，M=N=4 时与训练期 `forward_shared_observation` 的 `N·H=160` 完全同构，`_build_shared_obs_mask(num_offsets=M)` 直接复用。
- SDN 两阶段必须改：kNN 负集换成**配对 Δv**（代价 M×C token，且在 t=1/N 处灵敏度最强）；JerkRMS 必须加**接缝项 + 滞回**（chunk 内三阶差分对边界完全不敏感）。
- 成本结论：**M 不乘权重、不乘 KV cache**，显存增几十 MB；真正的闸门是 **G3（overlap 窗口）** 与接缝项，不是显存。

**五道闸门**（后续所有实验都在复用这套口径）：G1 正确性（M=1 逐位等价）、G2 动力学（buffer 逐位不变）、
G3 成本（`profile=True` 的 action 段）、G4 信号（离线排名相关度）、G5 效果（对照臂全开）。

## 3. P-1（11-19）：先把「SDN 到底值多少」量出来

这一天同时开了两条互不干扰的线，而且两个环境**完全隔离**（py3.10/torch2.3.1/cu118 vs py3.12/torch2.9.1/cu128，
`transformers 4.44.2` 与 `5.3.0` 只能活一个）。

### 3.1 R1：π0\* + SDN 原样复现（SIMPLER）

`sdn_r1_env.md` 是方案，实测后必须偏离 5 处（都记进 `sdn_r1_result.md`）：

1. `grep -rl bin/ | xargs sed -i` 会**打坏 27 个 ELF**（段表偏移错位，`bin/python -V` 直接 SIGSEGV）——只改文本文件；
2. `tensorflow[and-cuda]==2.15.0` 装不上（`tensorrt-libs==8.6.1` 已下架）→ 改 CPU wheel；
3. `bitsandbytes` 未钉版本会把 torch 顶到 2.14.1 + CUDA 13 → 钉 `0.44.1` + 补回 `nvidia-nccl-cu11`；
4. SAPIEN 缺 `libvulkan.so.1` → `conda install vulkan-loader`；
5. pip 26 不再自带 `pkg_resources` → `setuptools==75.8.0`。

单卡冒烟（GPU4）：2 条 episode × `widowx_carrot_on_plate` **2/2 成功**，显存峰值 **12.8 GB**，
日志读回 `negative_mode=zeros_bbox / N=12 / k=6 / M=3`——证明负样本与打分链真的在跑。

### 3.2 R3：π0.5 + LIBERO 非流式接入

`sdnrun.md` 的价值不在效果，而在**基础设施与成本剖面**：

- 离线闸门全 PASS：`N=1` 与基线**逐位相同**；`N=12` 只有 **2.58×**（次线性，因 bsz=1 时 GPU 远未饱和）。
- 候选确实有分歧：`candidate_std=0.113`，分数 2.25–3.14。
- 修掉三个真 bug：包装对象违反 `isinstance(policy, PreTrainedPolicy)` → 改 `attach_sdn()` 就地挂载；
  `N=1` 自递归；`noise` 参数在 N>1 分支被忽略（导致 G2 无法校验）。
- 四处环境坑：`CUDA_VISIBLE_DEVICES` 对 `eval.sh` 无效（要用 `GPUS`）、`~/.libero/config.yaml` 旧前缀、
  必须 `HF_HUB_OFFLINE=1`、`compile_model` 每换 batch size 就 autotune 5–10 分钟。

**这一天定下的口径**（后面一直沿用）：R3 的 `eval_s` 只能算比值（与 R1 并存时被拉高 2.2×）；
`results_pi05_baseline/ov0`（5 seed × 4 suite × 500 ep）是现成基线锚点。

## 4. P-2（11-20）：路线决策——把 R3 从关键路径上摘掉

### 4.1 `2.md` 的三个判断

1. **R3 作为「先验证 SDN 再上 FlashVLA」的前置是错的**：clean LIBERO 物体永远在位、object/spatial 基线已 97–98%，
   既呈现不出 grounding 增益，也测不到接缝与 overlap。定位降级为「滞后的同环境非流式锚 + 打分器开发台」。
2. **真正缺的是 SIMPLER 上的四个臂**（一个都没跑）：`vanilla`（分母）、`sdn_grounding`（Stage 1）、
   `sdn_smooth`（Stage 2）、`vanilla_perturbed`（判据：增益是否真来自定位）。
3. **能用 π0\* 训 FlashVLA，但不是「直接装载」**：拆权重后发现 π0\* 是**三流 joint attention**
   （vlm / action / **proprio**），而 flashvla pi05 只有两路；`joint_model.mixtures.*` 与
   `paligemma_with_expert.*` 命名完全不同；**流式能力只能靠训练获得**（π0\* 是 10 步 ODE，t=0.25 单步会显著掉点）。

路线 A（双环境，1–2 周单卡）vs 路线 B（统一到 SIMPLER，5–9 周 + 多卡）；当时选 A 起步，B 降级为 B0 三道门待查。

### 4.2 `3_0.md`：一票定性的 P0

| 判定 | 结果 |
| :--- | :--- |
| 问题 | pi0.5 能否直接在 SIMPLER 上工作？（若能，teacher 可换 pi05，跨架构自举就不必要） |
| 结果 | **0/45 = 0.0%**（9 任务 × 5 ep，seeds 100–104）；补做域内统计量重标定后**仍 0/5** |
| 诊断 | 不是管线 bug：`action_std` 0.19–0.21、gripper 13 个不同取值、EEF 位移 0.68 m |
| 归因 | 平移幅度是 SIMPLER 的 **5–30×**（LIBERO `dx.std 0.336` vs fractal 0.069 / bridge 0.0096），但重标定后仍 0% → 差在**视觉域与机器人形态** |
| 判定 | G0 不通过 → **teacher 必须是 π0\***，跨架构自举成立 |

附带产出：`scripts/p0/{pi05_server.py, simpler_client_eval.py}` 把「跨进程 server」这个 1–2 天的工程提前做掉一半，
后续 G3 与 P4 全部复用它。两处必须记住的坑：numpy pickle 不跨版本（只传 `bytes/list/str`）、必须 `HF_HUB_OFFLINE=1`。

### 4.3 `sdn/results.md`：R1 正式基线闭环

9 任务 × 50 ep = 450 ep，单卡 6 h 51 m，**67.3%（303/450）**，逐任务全部低于论文（均值 −5.2 pp）。
随后两天补齐的消融，把「SDN 到底哪个旋钮有用」这件事问清楚了（与 `all_results.md` 合并看）：

| 结论 | 数字 | 显著性 |
| :--- | :--- | :--- |
| 最优**单一固定**配置 | **`(k=6, M=3, lh=4)` = 70.7%** | — |
| `lh` | 4/5/10 = 69.1 / 68.7 / 65.4 | **lh=10 显著更差**（合并 McNemar p=0.0012，四组配置 4/4 同向） |
| `k` | 6 vs 10 = 68.4 vs 67.1 | +1.3，p=0.11，不显著（方向与论文一致） |
| `M` | 5 vs 3 = 67.6 vs 67.8 | **p=0.86，完全无效应**（论文搜索空间里的空维度） |
| 逐任务逐格最优拼接 | 75.8% | **同 seeds 选优 → 乐观，不能当超过论文** |
| 确定性 | 3 组重复格逐 episode 全同、14 个 root 零冲突 | 通过 |

两处方法论收获：
- 论文 Table II 的 50 rollouts 与其数字**不自洽**（SDN 行有 87/89/63 等奇数；base 行的 .7/.3 指向 3×100=300），
  所以本项目的定位只能是「同协议下的相对比较」，不宣称复现绝对值。
- `lh=10` 的伤害集中在 `open_drawer`（−16）、`put_eggplant`（−9）、`place_apple`（−7.5），
  而 `coke`（+6.5）、`move_near`（+3.0）反而受益——**加长 JerkRMS 窗口会让候选偏向「少动/慢动」**。

### 6.2 三个「不是玄学」的技术发现

1. **preprocessor 序列化 bug（影响面最大）**：`FlashVLAPi05PrepareLanguageProcessorStep` 没重写 `get_config()`，
   保存出来是 `config: {}`，重新加载时用字段默认值 → **`state_cond=False`**（训练用的是 `True`），
   prompt 从 12 token 变成 46 token。定量影响：loss 0.3080 → 0.1620；闭环 `stack_cube` 10 seeds **0/10 → 5/10**。
   修两处（补 `get_config()` + 在 `make_pre_post_processors` 用 `policy_cfg` 兜底 override），
   所有走 `pretrained_path=` 的路径（`sim_eval/robotwin`、`benchmarks/`）一起修好。
2. **`state_cond` 实际上是死的**：换 `observation.state` 只让动作变 6.6e-5；`state_mlp_out|w| = 9.68e-6`。
   后续 Q3 小实验证明两个「便宜修法」（10× lr / 小随机初始化）都不行：梯度健康（|grad|=0.214）但权重不动，
   bf16 在 1e-4 量级已低于有效更新分辨率；且 state 支路 1e-5 与 `time_emb` 的 1.58e-2 **差两个数量级**，
   「乘法性杠杆够不到加法性缺口」。
3. **`--resume` 不是「再训 N 步」**：非 FSDP resume 会连 lr scheduler 状态一起恢复，原配置到 4000 步时 lr 已在
   地板 2.5e-07 → `004000→006000` 那 2000 步几乎没有学习。要测「多训有没有用」必须**新开 run**。

### 6.3 顺带的两个执行层教训

- IDE 插件注入的 `sitecustomize.py` 把 `Path.unlink` 改成「移进回收站」，在 `/data` 上必崩

## 7. P-5（11-23 → 11-24）：换领域先验——π0\* 移植

### 7.1 `4_pi0star_flashvla.md`：不经过 pi05，直接映射进 `pi0-flashvla`

**为什么**：pi05 路线失败在「域」不在「流式」（起点是通用 `pi05_base`），而 π0\* 是**已经在 SIMPLER 上训过**的同族 π0。

**映射结果**（`scripts/p4/convert_pi0star.py`）：

| 项 | 值 |
| :--- | :--- |
| 源 → 目标 | 938 张量 → **774 映射 + 165 丢弃 + 5 合成 = 779** |
| 丢弃 | `mixtures.proprio.*`（163）+ `proprio_encoder`（2）= **311.47 M = π0\* 的 8.8%** |
| 关键手工处理 | `embed_tokens` 257216→257152 截 64 行；`lm_head` 复制截断后的 embedding（要 `.clone()`）；`action_in_proj` 右侧补 25 列零；`action_out_proj` 下方补零行 |
| 合成 | expert 的 `embed_tokens`/`lm_head` 置零、VLM 末端 norm 置 1、`state_proj` 置零 |
| 加载 | `from_pretrained` 成功，4,291.34 M 参数，`action_buffer (1,16,32)` |
| 吞吐 | **2.17 s/step @ bs=4**（峰值 25.4 GB），比 pi05 的 5.06 s 快一倍多（1 视角 473 token vs 3 视角 985 token） |

**一个关于 loss 的口径陷阱**：`action_in_proj` 的 7–31 列与 `action_out_proj` 的 7–31 行被置零，
而 noise 在 32 维采样 → 那 25 维**既看不到输入也发不出输出**，恒定贡献 `E[noise²]=1.0`，
总 loss 的 `25/32 = 0.781` 是硬地板。折出真实 7 维：π0\* init L7 ≈ 4.3，pi05 起点 1.46。
**所以「π0\* 比 pi05 差 5 倍」是 padding 造成的错觉**，真实维差距 1–3 倍。

### 7.2 `pi_star_analysis.md`：12.5% 的归因（以及自我推翻）

bridge 四个任务：carrot 8% / eggplant 36% / spoon 6% / stack_cube 0% = **12.5%**（π0\* 原生 80%）；
fractal `close_drawer` 46%（原生 68%）。先排除三个「看起来像」的嫌疑：评测协议（pi05 005000 逐任务完全复现 59.00%）、
服务端推理路径（离线探针 MAE 0.0754 <「永远输出均值」0.1515）、`empty_cameras=0`（π0\* 本来就只有 1 张图）。

提出的三条机制：**A 归一化口径错位**（`bound` 的 std ≈0.45 vs `MEAN_STD` ≈1.0，要头部整体放大 1.84–2.35×）、
**B 32 维零填充吃掉 78% 梯度**（实测填充维权重的 rms 4000 步后仍 1e-5 量级）、
**C proprio 通路被摘掉**（`state_proj` rms 1.7e-5，彻底 state-blind）。

**fractal 同病但只掉 22 pp 而不是 67 pp**，三个放大器：3× 优化步数（12000 vs 4000）、预训练见过该域（起点 L7 2.12 vs 4.01）、
任务对精度不敏感（`close_drawer` 是单相位「推上去关掉」）。

**然后 F5 实测把主因 A 推翻了**（这一节是本路线最诚实的地方）：

| 口径 | 初值 L7 | grip 维 |
| :--- | ---: | ---: |
| `QUANTILES` | **4.14** | **19.08** |
| `MEAN_STD` | **4.59** | 17.47 |

- F1（换回 QUANTILES）只值 **−10%**，不是预测的 −70%；L7 的 77% 来自**夹爪通道**；
- 「MEAN_STD 要求整体放大 1.95×」**方向相反**：MEAN_STD 下头输出是**偏大**的（v/u 1.1–1.4）；
- 500 vs 500 的部署路径探针：F1 只改善夹爪，**6 个运动维全部变差**（dx −36%、rx −44%…）。
- 结论：**12.5% 的主因需要重新归因**——现有证据只支持「π0\* 的头部在 FlashVLA 结构里初始化后与目标不相关、要靠训练学，
  且夹爪通道在初值阶段吃掉大部分梯度」，不再支持「归一化增益错位」。
- 顺带修掉一个真 bug：`scale_state_path_lr` 在 scheduler 建好之后才加 param group，导致第 1 组 lr 永远停在 warmup 初值
  （且续跑必崩 `List length mismatch`）→ **过去所有 `state_path_lr_mult` 实验其实都没生效**。

## 8. P-6（11-25 凌晨 → 中午）：把 π0\* 的 proprio 通路接进来

### 8.1 `f6.md` 总纲：一个方案级的源码事实

π0\* 的「三路 mixture」不是复杂交叉注意力，而是**一条因果序列上的三个 token block**：
`[vlm 2048] → [proprio 1 token] → [action 4 token]`。而且：

> **`mixtures["proprio"] = mixtures["action"]`**（`pizero.py:274-276` 的 `tie_action_proprio_weights()`），
> 两份官方 ckpt 里这两组张量**逐位相同、同一 storage**。

所以 `.pt` 里 165 个 `mixtures.proprio.*` 是 action 栈的**重复序列化**，转换时应丢弃；
π0\* 真正 proprio 专有的**只有一个输入编码器**（fractal `(1024,8)` / bridge `(1024,7)`）。
→ 三路相对两路**只多 `proprio_in_proj`（≈8.2 K 参数）**，不是 311 M 的第三套 decoder。

而 FlashVLA 的 suffix 布局**已经与它同构**：每个 buffer 配置的 suffix 首位就是一个 state token（`att_mask=1` 自成 block），
mask / position 一个字都不用改。

### 8.2 四个阶段的结果

| 阶段 | 内容 | 关键结果 |
| :--- | :--- | :--- |
| **S0** | 把 `proprio_encoder` 装进 `state_proj`（零框架改动） | **弱 GO**：2000 步 A/B 在 **6/6 运动维 + 夹爪**全面更优，`mae 0.1361 → 0.1225`（−10%）；`corr(dx)` 只 +0.023（两臂都还在 0 附近，无分辨力） |
| **S1** | `use_proprio_stack` / `proprio_dim` / 转换器开关 | 完成，但「独立第三路 311 M 栈」方案在 S2 被**取代** |
| **S2/S3** | 三路前向（共享 action 权重）+ 三条推理路径 | 两路路径**逐位守恒**（CPU fp32 与 GPU bf16 的 `max|diff| = 0`）；老 ckpt 探针数字**逐位不变**（差 0.0）；6 条单测 225 s |
| **S4** | bridge 的 7 维 `POS_EULER` | 与 π0\* 参考实现 **`max|Δ| = 4.44e-16`**；16 条单测 0.02 s |
| **S5** | 三臂 A/B（各 2000 步） | **GO，但归因反转**（见下） |
| **S6** | 8000 步长跑 N1 / N2 | N1 有效、**N2（lr×10）判否** |

三个必须记住的修正：

1. **π0\* fractal 的 proprio 与我们的 state 只同形不同序**（`[x,y,z,qx,qy,qz,qw,1-grip]` vs `[x,y,z,qw,qx,qy,qz,grip]`），
   8 维里错 5 维 → 加 `--proprio-layout flashvla_quat`（纯置换 + 符号，折进权重，数值自检 2.4e-7）。
2. **S4 的「归一化先按现状跑」做不到**：quat→euler 是非线性的，必须在 Normalizer **之前**做；
   且 8 维统计量喂 7 维会直接报错 → 实际做法是「QUANTILES 口径不动 + 为 7 维新造统计量」。
3. **500 步屏幕在同 epoch 口径下无效**：fractal 5,315 步/epoch，500 步 = 0.09 epoch，两臂都还差于「预测均值」基线。
   **屏幕必须按 epoch 标定**。

### 8.3 S5 的核心结论（与规划相反）

| 臂 | 模型 | `mae_overall` | 6 运动维均值 | `corr(dx)` | 夹爪二分类 |
| :--- | :--- | ---: | ---: | ---: | ---: |
| ① | 两路 + 编码器装 `state_proj` | 0.12254 | 0.06533 | −0.021 | 0.7708 |
| ② | 三路 + **随机** `N(0,0.1)` 编码器 | 0.12370 | 0.07307 | −0.007 | 0.7917 |
| ③ | 三路 + **π0\* 编码器** | **0.10343** | **0.05984** | **+0.110** | **0.8229** |

- ③ vs ①：6/6 运动维 + 夹爪全胜，`corr(dx)` **+0.131**（阈值 +0.05），`mae_overall` −15.6% → 判 GO。
- ② vs ①：运动维 **+11.8%（更差）**，6 维只赢 1 维 → **「多一个 block」本身没有价值**；随机投影在共享权重下是**有害偏置**。
- 且这不是「③ 学得更多」：三臂的输入投影在 2000 步里位移都在同一量级（`cos ≈ 0.9995`）。
- **一句话：价值在权重，不在结构。** 这直接否定了 `f6.md` §1「只多 8.2 K 参数因此几乎免费」的乐观读法。

### 8.4 S6 长跑的两个反转

- **S5 的三臂其实是「短配方」**：`steps=2000 < num_decay_steps=12000` 触发调度器自动压缩
  （`lerobot/optim/schedulers.py:99-112`），实际是 **83 步 warmup + 2000 步退火**，2000 步时 lr 已到 2.5e-7。
  → 任何跨 `steps` 的对照都要先对齐这条，**同 step 不同 `steps` 的绝对指标不可比**。
- **N1（臂③ 8000 步）单调变好，6000 步饱和**：运动维均值 `0.05274 → 0.04697`（vs ③@2000 −21.5%，vs ①@2000 −28.1%），
  `corr(dx) +0.321 → +0.369`；6000→8000 只再降 0.3%。**加步数有效，但收益主要来自「更长的 lr 寿命」**。
- **N2（`state_path_lr_mult: 30`）判否**：`proprio_in_proj` 位移放大 **5.7–8.9×**（`cos 0.926` vs N1 `0.997`），
  但 4/4 个探针点上 6 个运动维全部打平（≤1%）→ 那张 8.2 K 的表**不是精度瓶颈**。

## 9. P-7（11-25 下午）：SIMPLER 部署闸门——链路无罪，分数有罪

`f7_next_steps.md` 把「FlashVLA 在 SIMPLER 上能不能跑通并给出可引用分数」这件事推进到只差一个变量。

### 9.1 F1：单任务 × 50 seeds × 4 个 ckpt

| ckpt | 配方 | 成功率 | 完全没动（qpos>0.12） | 中位 qpos |
| :--- | :--- | ---: | ---: | ---: |
| π0\*（T0 参照） | in-process，非蒸馏 | **68%** | 7 | 0.017 |
| 老锚点 `012000` | **MEAN_STD** + 两路 + 12000 步 | **46%** | 15 | 0.057 |
| **N1 8000** | **QUANTILES** + 三路 + 8000 步 | **34%** | 22 | 0.107 |
| N1 6000 | 同上 | 28% | 28 | 0.132 |
| 臂③ 2000 | 同上 | 24% | 33 | 0.154 |

**三条已核实的结论**：

1. **链路没问题**：state（8 维 raw `eef_pos`）、相机（`overhead_camera`）、夹爪（±1 命令）三条口径全部对上，
   4 个 ckpt 都能跑满 50 集（单 ckpt ≈20 min）→ 分层定位表 L2–L6 **一次通过，以后不必再查链路**。
2. **闭环分数随步数单调改善但斜率很缓**：24% → 28% → 34%，约 **+1.7 pp / 1000 步**；外推到 12000 步也只有 ~40%，
   **不足以解释老锚点的 46%**。
3. **离线 MAE 能排名、不能定分**：四个 ckpt 的离线运动维 MAE 与闭环成功率**严格同序**
   （0.04544→46% > 0.04697→34% > 0.04712→28% > 0.05984→24%），
   但 0.003 的离线差对应 12 pp 的闭环差。

### 9.2 头号嫌疑：`QUANTILES`（F1）

老锚点与新 ckpt 差**三个变量**（归一化 / 步数 / 路数），但失败结构指向归一化：
近失手率（0.05–0.08）三家基本没变（8/9/4），而「完全没动」随配方劣化单调上涨（7→15→22→28→33）。
机制假设：`QUANTILES`（p01/p99 → [−1,1]）在**闭环**里会把超出训练分布的 state **饱和截断**，
智能体被自己带出分布后就「失去分辨率、拉不回来」；`MEAN_STD` 仍线性保留尾部。

⚠️ 这是**假设**不是结论。验证成本极低：一行配置（`STATE/ACTION: MEAN_STD`）+ 5 h 训练 + 22 min 评测。
yaml 已生成（`_f7s1_meanstd.yaml`，与 `_f6s5_3_8000.yaml` 只差 4 行），分流判据也已写死：

| MEAN_STD 结果 | 含义 | 下一步 |
| :--- | :--- | :--- |
| **≥46%** | 归一化是主因 | 全线回退 MEAN_STD，重跑关键臂 → 五任务闸门 |
| 38–45% | 各占一半 | 追加 `12000 步 + MEAN_STD` |
| ≈34%（±SE） | 归一化无罪 | §7 O1（MEAN_STD + 两路 8000 步）分离结构，再 D1 扩数据 |
| <30% | 同向恶化 | 停下复查链路，别继续加臂 |

### 9.3 后续路径（已排好序）

`P0 MEAN_STD 单变量` → `§7 O1 两路同位对照` → `§6 D1 扩成功轨迹`（再采 seeds 1200–1599，≈400 集/任务）。
五任务闸门的判据是 `macro ≥ 0.544`（T0 五任务 0.564 − 2 pp），且**只有 close_drawer ≥46% 时才有解释力**。

### 10.3 五条方法论纪律（写进任何后续实验）

1. **单变量**：一个臂里不要同时改归一化/掩码和架构；跨 `steps` 的 run 要先对齐 lr 轨迹。
2. **判据要 scale-free**：绝对 loss 不可跨归一化口径比（QUANTILES 地板 ≈1.2、MEAN_STD ≈2.0）；
   `mae_overall` 不可单独用（被夹爪主导）；≤3 pp 的夹爪二分类差异是 1 个样本的噪声。
3. **屏幕按 epoch 标定**：fractal 5,315 步/epoch、bridge 1,005 步/epoch；500 步在 fractal 上什么都测不出来。
4. **确定性先验**：同 seed 重跑逐位一致是所有配对比较的前提（P1 已验到 mp4 字节、SDN 已验到逐 episode）。
5. **口径先于数字**：G3 的分母必须同 seeds（采数 1000–1499 / 评测 2000–2049 / R1 0–49 三方不相交）。
