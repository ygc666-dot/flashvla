# SDN × FlashVLA：可行性分析与两种接入方案

> 本文是「把 SDN（Selected Diffusion Noise）接入 FlashVLA 流式推理」的分析记录与方案对比。
> 目标不是刷点，而是先把**机制上是否成立**、**代价落在哪里**、**哪条路值得做**这三件事定下来。
>
> 关联文档：`flashvla/docs/papers/SDN - Selected Diffusion Noise.md`（方法原文）、`flashvla/docs/analysis/code_analysis.md`（FlashVLA 实现分析）、`flashvla/docs/doing/try/pcd.md`（PCD 接入方案，可复用的全部基础设施）。
> 代码引用格式 `起始行:结束行:文件路径`，路径相对 `flashvla/` 仓库根。
> 运行示例采用 LIBERO 配置：`N=num_buffer_slots=4`、`C=chunk_size=10`、`n_action_steps=5`。

---

## 0. 结论摘要

1. **大方向成立，且 FlashVLA 是 SDN 的天然搭档**，理由是一个结构性的「深度 ↔ 宽度」换算（§2）。
2. **但有一个必须先修正的误解**：FlashVLA 的 N 个槽**不是 N 个候选**，而是**同一条流水线队列里 N 个不同噪声样本的不同成熟度**。按字面理解实现会得到一个数学上不成立的东西（§1）。
3. **SDN 的两阶段不能照搬**：kNN 负集在流式下太贵、且独立性假设易被破坏；JerkRMS 测不到流式特有的接缝跳变（§4）。
4. **两条自洽路线**：方案 1（单 buffer，只动 slot 0，重噪出候选）成本低但只能治抖动；方案 2（M 条并行流水线）能拿到满多样性、受 overlap 窗口约束（§5、§6）。
5. **真正的可行性闸门是 overlap 窗口，不是显存**。“M 倍显存”是伪问题（M 不乘权重、不乘 KV cache），见 §7。
6. 建议：**先用方案 1 做探针**确认“读出侧选择是否有信号”，再用方案 2 换多样性（§9）。

## 1. 必须修正的误解：N 个槽 ≠ N 个候选

### 1.1 事实

稳态每次调用（`policies/pi05/modeling_pi05_flashvla.py:1009-1022`）：

```
输入 slot 时间   [0.25, 0.50, 0.75, 1.00]
输出 slot 时间   [0.00, 0.25, 0.50, 0.75]   ← slot 0 读出执行
左移后           [旧slot1, 旧slot2, 旧slot3, 新噪声]
```

跟踪**某一条噪声样本**（N=4）：

| 调用 | k | k+1 | k+2 | k+3 | k+4 |
| :--- | :-- | :-- | :-- | :-- | :-- |
| 所在槽 | slot3 | slot2 | slot1 | slot0 | **被执行** |
| 该槽 t | 1.00 | 0.75 | 0.50 | 0.25 | 0.00 |

**槽 0~3 是同一个队列里排队的 4 个不同噪声样本，各自处在不同成熟度**，不是同一时刻的 4 个备选答案。

### 1.2 一个看起来可行但实际错误的变体

“把 slot 1/2/3 各自补足到 t=0，代价只有 (2+3+4)×C = 90 token，几乎免费”——**这个变体是错的**：

- 槽 j 的样本是**给未来第 j 次调用准备的**（slot3 的样本在 k+4 才执行）。提前推到 t=0 得到的是“**未来某个时间窗口**的动作”，与 slot 0 的目标时刻不同，两者不可比。
- **成熟度不等**：slot 3 从纯噪声只用 1 步跨到动作（等价 1-step 蒸馏），slot 0 用了 4 步。比较时无法分离“噪声种子差异”与“去噪步数差异”。

**结论：要拿到 M 个可比的候选，唯一办法是维护 M 条同步的流水线**（各自独立 buffer / 噪声，共享同一 `step_counter`），使 M 个 slot-0 chunk 同为“目标窗口 = 当前时刻”。

## 2. 为什么仍然值得做：深度 ↔ 宽度换算

FlashVLA 把 ODE 的**深度**摊平成**跨调用的时间**，于是“多要几个候选”变成纯粹的**宽度**问题；宽度在 batch=1、带宽受限的推理里几乎是免费的。

| 方案 | 每次候选数 | suffix token | **串行步数** |
| :--- | :--- | :--- | :--- |
| π0 基线 | 1 | 100 | **10** |
| π0 + SDN (N=12) | 12 | 1200 | **120** |
| FlashVLA 基线 | 1 | 40 | **1** |
| FlashVLA + M=4 流水线 | 4 | 160 | **1** |
| FlashVLA + M=12 流水线 | 12 | 480 | **1** |

> 可写进论文的一句：**FlashVLA 把 best-of-N 从“延迟×N”变成了“吞吐×N”。**
> 且 M=4 的 token 量（160）只比“放弃 FlashVLA 退回 π0”（100）多 60%，串行步只有其 1/10 —— 只要 M ≲ 10，在 token 口径上都比退回 π0 便宜。

### 2.1 一个几乎免费的巧合：M=N

M=4 时稳态 suffix 形状为 `[B, 4×4×10] = [B, 160]`，与训练期 `forward_shared_observation` 的 `N·H = 160` **完全相同**（`modeling_pi05_flashvla.py:755-779`），且注意力拓扑同构：

| | 训练 | 推理 + M=4 流水线 |
| :--- | :--- | :--- |
| suffix 总长 | N·H = 160 | M·N·C = 160 |
| 组间隔离 | `cross_offset_mask`（`:686-696`） | 同左，`num_offsets=M` |
| 组内 | N 槽 × C，块因果、每槽一块 | 同左 |
| pad 语义 | 配置 k 只前 kC 真 | 全真（更简单） |

即 **`_build_shared_obs_mask(..., num_offsets=M)` 可直接复用**，不需要新的 mask 逻辑，静态形状不变，`torch.compile` 仍单图、CUDA Graph 仍只捕获一次。唯一要改的是把 `denoise_step`（`:841-869`）里的 `build_attention_mask_and_position_ids` 在 M>1 时换成 `_build_shared_obs_mask`。

## 3. 两阶段在流式下的必要改造

| SDN 原文 | FlashVLA 版本 | 为什么变 |
| :--- | :--- | :--- |
| N=12 个独立噪声样本 | M 条同步流水线 | 一次调用只能给一条流水线一步 |
| Stage 1：kNN 密度比 $d_\mathcal{B}-d_\mathcal{G}$ | **配对 $\Delta v$ 逐候选打分** | 负集采样太贵；且正集样本强相关时 $d_\mathcal{G}$ 被低估 |
| Stage 2：JerkRMS on 延长 chunk | JerkRMS on C=10 **+ 接缝项 + 滞回** | chunk 固定长度、流式有边界，SDN 无此项 |
| 每步重采样 | 候选在时间上连续演化 | FlashVLA 的候选是“活”的，不是用完即弃 |

### 3.1 用配对 Δv 替掉 kNN

对候选 i，在它自己的 $x_i$（t=1/N 的 slot 0）上分别用干净 prefix 与掩码 prefix 算速度：

$$\Delta v_i = v_\theta(x_i, 1/N, e_{\text{clean}}) - v_\theta(x_i, 1/N, e_{\text{masked}})$$

- 代价：**M×C token**（只需 slot 0 那一个块），不需要 M′ 条常驻负流水线。
- 方向性：由 `pcd.md` §1.2 的 N′=1 推导，密度比在候选点上的对数 $\propto \|\Delta v\|^2/2b^2$，即 **$\|\Delta v\|$ 越大 ⇒ 动作越依赖目标物体 ⇒ 越 grounded ⇒ 越好**（与 SDN“远离负集”同向）。
- 落点极巧：`pcd.md` §1.3 证明敏感度为 $(1-t)/t$，**$t=1/N$ 处是整个流水线最强的位置**（比 t=0.75 强 9 倍）。

> 建议实现 `‖Δv‖/‖v_o‖` 与 `1-cos(v_o,v_ô)` 两版，用 `pcd.md` §5.2 的离线教师强迫实验定方向；`pcd.md` 的 T3 就是同一个量的雏形。

**附带优势**：SDN 用**选择**而非**引导**，天然避开 `pcd.md` §1.4 担心的“α 把状态推出训练分布”的风险。选择的安全性严格优于引导 —— 这是选 SDN 而不是 PCD 的正当理由。

### 3.2 接缝项（流式特有，SDN 缺失）

选出另一个候选的 chunk 会在边界产生位置阶跃，而式 (9) 的 $S$ 是 chunk **内部**三阶差分，**对边界完全不敏感**。若照搬，会出现“JerkRMS 变好、成功率变差”的典型反向结果。

$$S_i = \underbrace{\text{JerkRMS}(\mathbf{A}_i)}_{\text{chunk 内平滑}} + \lambda \underbrace{\|a^{(i)}_0 - a_{\text{prev}}\|}_{\text{接缝连续}} + \mu \underbrace{\mathbb{1}[i \neq i_{\text{incumbent}}]}_{\text{滞回}}$$

- 接缝项 ≈ 免费的“留在分布内”先验（对应 SDN 引用的 [46] LPB 思路）；
- 滞回项防止候选高频翻转（每 5 个控制步换一次模式，比不选更糟）；
- 注意 `C=10` 但 `n_action_steps=5`，**只有前 5 条被执行**，接缝项应主要权重在 $a_0$。

## 4. 方案 1：只在执行前一步，从 slot 0 生成候选与负样本视图

### 4.1 核心逻辑

单 buffer 不动，读出时以 slot 0（$t=1/N$）为根扩出候选：

1. **候选（重噪）**：$x_{t'}=t'\varepsilon_j+(1-t')\,x_{\text{slot0}}$，再跑 $m=t'N$ 步欧拉到 0；M 个 $\varepsilon_j$ 得 M 个块。
2. **负样本视图**：同一 $x$ 换掩码 prefix 得 $v_{\hat o}$，不采负样本集，只用配对 $\Delta v$ 打分。
3. **合并打分**：$\|\Delta v\|/\|v_o\|$ + JerkRMS + 接缝 + 滞回 → argmin 执行。
4. slot 0 读出即被丢弃（`:1021` 左移不保留），故 buffer 演化逐位不变。

### 4.2 关键定量：多样性 = 串行深度

由路径 $x_t=t\varepsilon+(1-t)a$，给定 $x_t$ 时动作的后验标准差 $\mathrm{std}(a\mid x_t)\approx \frac{t}{1-t}\sigma$。$N=4$ 时 slot 0 的 $t=0.25$ → 仅 **0.33σ**。

| 方案 | 串行步 | 额外 token | 可达多样性 | 能否跳模式 |
| :--- | :--- | :--- | :--- | :--- |
| 步长族（同 $v$ 配不同 $\tau$） | 1 | 0 | 0（共线，退化） | 否 |
| 重噪 m=2 | 2 | 80 | ≈0.5σ | 极小 |
| 重噪 m=3 | 3 | 120 | ≈0.75σ | 有时 |
| 单次全 ODE m=4 | 4 | 160 | 1.0σ | 是 |
| M 条并行 buffer（M=12） | **1** | 480 | 1.0σ | 是 |

**多样性只能从“往上重噪到多高”里买，而重噪到 $t'=m/N$ 就必须付 m 步串行。**

### 4.3 优点

1. **改动最小**：不扩 buffer 维、不碰 `reset` / cold start / `warmup` / `skip_stale_actions`；开关控制，M=1 逐位回退。
2. **动力学天然不变**（`pcd.md` 的 T2 直接成立），**零 M 倍显存**。
3. **在分布内**：重噪是“插值点重启 ODE”，比速度引导安全，避开越界风险。
4. 掩码 prefix 可与正 prefix 折 2B，一次 prefill。

### 4.4 缺点

1. **多样性受限于串行深度**（m=2 仅 0.5σ）。
2. m 增大即退回多步推理，FlashVLA 的低延迟优势被侵蚀。
3. 破坏 SDN 阶段 1 的独立性假设（M 个候选共享前 N−1 步历史 → 近邻几乎是“同胞”，$d_\mathcal{G}$ 被系统性低估约 $(1/m)^{1/D}$），**必须换配对 Δv，本质退化为“PCD 的候选选择版”**。
4. 负样本视图依赖检测器（多相机全掩、首帧冻结），精度直接决定打分质量。
5. 期望效应量小：只覆盖 smoothness 那一半，而这半在流式下已被 4 次观测平均部分承担。

### 4.5 核心风险

1. **无多样性 → 无选择**：候选几乎共点，增益≈0 而成本实付。
2. **修不了模式级失败**：抓空/错物在 $t=0.25$ 已成定局，0.5σ 内跳不出模式间隔 —— 而这恰是 SDN 的真实收益来源（Table III：Grounding 单独 +13.33%）。
3. **打分方向可能反**：Δv 大未必等于 grounded，须离线验证，否则会选到最依赖物体的离群点。
4. **掩码不彻底**（只掩 agent view、wrist 里物体仍在）→ 负集失真 → 打分随机。
5. 易被识破为“自适应步长”而非“选择”。

### 4.6 能修 / 不能修

| 失败模式 | 单 buffer 只动 slot 0 |
| :--- | :--- |
| chunk 内高频抖动、末端振荡 | **能修**（局部形状在 0.5σ 内可调） |
| 边界接缝跳变 | **能修** |
| 抓空 / 物体错位（grounding 级） | **修不了**（错误模式在 t=0.25 已定） |
| 整体任务方向选错 | **修不了** |

## 5. 方案 2：M 条流水线并行 + 读出侧 SDN 选择

### 5.1 核心逻辑

buffer 扩成 `[M, B, N·C]`，M 条流水线各自独立噪声、独立 buffer、共享同一 `step_counter`：

1. prefix **只编码一次**，K/V 被 M 条共用；
2. suffix 拼 `[B, M·N·C]`，用 `_build_shared_obs_mask(num_offsets=M)` 做跨流水线隔离 + 每槽块因果；
3. **一次** denoise（1 串行步）→ 同时得 M 个 slot-0 chunk；
4. 各自 `buffer -= dt·v`、左移、尾部灌新噪声；
5. 读出侧打分 → `argmin` 交给执行器，其余丢弃但继续演化。

**关键不变量**：每条流水线仍严格是合法的 FlashVLA 流水线；选择只影响“读哪一条”，不改进任何 buffer 的演化（故 T2 可移植）。

### 5.2 优点

1. **串行深度恒为 1**，只增宽度：M=12 是 480 token/1 步，π0+SDN 是 1200 token/120 步。
2. **满多样性**：候选来自真正的 $t=1$ 独立噪声，能修模式级失败。
3. **实现近似零新增**：M=N=4 时与训练期联合前向同构（§2.1），mask / compile / Graph 全复用。
4. 每条流水线严格合法，**动力学逐位不变**。
5. kNN 独立性成立，SDN 两阶段可原样使用（也可换更省的配对 Δv）。

### 5.3 缺点

1. M 倍 suffix 算力（M=4 约 1.5–2×，M=12 约 3–4×，见 §6）；显存仅激活增几十 MB。
2. **引入接缝不连续**，JerkRMS 测不到。
3. 需把 `reset`（`:1180-1190`）/ cold start（`:921-950`）/ `warmup` / `skip_stale_actions` 的 incumbent 状态 M 化，易漏。
4. 候选共享观测窗口（一次执行的 chunk 条件在最近 N 次观测上，约 20 个控制步），非严格“同观测”，论文须显式声明。
5. 必须每步推进否则失同步，**无法“偶尔做 M 路”**，只能整段固定 M。

### 5.4 核心风险

1. **overlap 窗口击穿 → 加速收益归零**（最致命）。FlashVLA 的收益全在“推理躲进 `env.step`”（`async_manager.py:176-191`），LIBERO 的 `env.step` 约 20–40 ms，余量本就薄。
2. **接缝跳变**：JerkRMS 只看 chunk 内部，会“指标变好、实机变差”。
3. **增益来源混淆**：可能来自“多算 M 倍”或“用了更新观测”（尤其若在读出时跑全 ODE），须用随机选 / 均值集成 / matched-compute 隔离。
4. 候选间距离过小（共用窗口）→ 选择无力。
5. clean LIBERO 无可破伪相关 → 白跑算力（见 `pcd.md` §9.2）。
6. M 进入 Python 控制流会引起 dynamo 重编译，破坏单图捕获。

## 6. 成本与显存：把“M 倍”这个说法修正掉

### 6.1 显存几乎是免费的

| 项 | 随 M 增长 | 量级（N=4, C=10, d=1024, bf16, M=12） |
| :--- | :--- | :--- |
| 模型权重 | **否** | — |
| prefix K/V cache | **否**（M 条共用一份 prefill） | 不变 |
| suffix 激活 | 是 | 480 token × 1024 × 2B ≈ 1 MB/张量，峰值几十~一百 MB |
| attention mask | 是（$L_{tot}^2$） | 1180² × 2B ≈ 2.8 MB |
| action buffer | 是 | 12×4×10×32×4B ≈ **61 KB** |

**M 不乘参数、不乘 KV cache**（suffix 不做 cache），乘的只是一个小激活张量。

### 6.2 算力只乘“action 段”

`profile=True` 已把三段分开（`:1024-1032`）：`encode` / `prefill` / `action`。prefill 要过约 700 个 prefix token，suffix 只有 40 个，**suffix 本来就是少数段**。

| M | suffix token | 若 action 占基线 25% | 若占 50% |
| :--- | :--- | :--- | :--- |
| 2 | 80 | ~1.25× | ~1.5× |
| 4 | 160 | ~1.5–2.0× | ~2.0–2.5× |
| 12 | 480 | ~3.0× | ~4.0× |

注意 suffix 需 attend 到 prefix K/V（代价 ≈ $L_{suf}\times L_{prefix}$），M=12 时 `480×700` 会超过 prefill 量级，故 M=12 确实重。**M=4 是甜点，M=2 最安全。**

> **必须先测一次三段占比，再决定 M。这一个测量就能把争论变成数字。**

## 7. 验证方案

### 7.1 五道闸门（按序，前两条不过即停）

| 闸门 | 判据 | 抓住什么 |
| :--- | :--- | :--- |
| **G1 正确性** | M=1 时逐位等于基线；M>1 时每条流水线 == 独立跑 M 次 | 掩码 / 位置编码 / KV cache 串味 / fold 顺序 |
| **G2 动力学** | 选择前后 `action_buffer` 逐位不变 | 是否把“读出侧选择”做成了“引导” |
| **G3 成本** | `profile=True` 测 `action` 段 M/B 比；M=4 >1.8× 就降 M；再看端到端 `avg_episode_walltime_s` | **唯一的硬闸门**，overlap 是否还成立 |
| **G4 信号** | 离线候选排名与 GT 误差的相关度；`ratio_背景 vs ratio_物体` 通道遮挡诊断（`pcd.md` §9.3，30 分钟） | grounding 通道在目标 benchmark 上是否有可矫正空间 |
| **G5 效果** | 对照臂全开，clean 与 perturbed 分层，同 seed 准配对 McNemar | 增益是否来自“选择” |

### 7.2 必跑对照臂（前两条最容易被审稿人问）

| # | 对照 | 回答什么 |
| :--- | :--- | :--- |
| 1 | **随机选一个候选** | 增益来自“选择”还是“多算 M 倍”？ |
| 2 | **均值/中位数集成（medoid）** | 选择是否真的优于平均？medoid 版不需要掩码/检测器，是**最干净的首次实验** |
| 3 | SDN 去掉 Stage 1 / 去掉 Stage 2 | 两阶段各自贡献 |
| 4 | matched-compute（M 条流水线但只执行第 0 条） | 排除纯算力效应 |
| 5 | 重噪幅度递增（m=1,2,3,4） | 直接画“多样性 → 增益”曲线，验证 §4.2 的单调关系 |
| 6 | 反事实类型：物体掩码 / 同面积随机矩形 / 陈旧帧 | 若随机矩形等效，机制不是 grounding |

## 8. 风险汇总

| # | 风险 | 影响 | 缓解 |
| :--- | :--- | :--- | :--- |
| 1 | **overlap 窗口击穿** | 加速收益归零（最致命） | G3 反推 M；降 M=2；或只保留接缝/JerkRMS（零额外算力） |
| 2 | **接缝跳变** | 指标假好、实机变差 | 接缝项 + 滞回；离线先测“选中率 vs 翻转率” |
| 3 | 增益来源混淆 | 结论不可信 | 随机选 / 均值 / matched-compute |
| 4 | 候选多样性不足 | 等价于没有选择 | 先测 M 个 chunk 的两两距离分布；单 buffer 时看 m 曲线 |
| 5 | kNN 独立性失效 | grounding 打分失真 | 改用配对 Δv |
| 6 | 掩码不彻底（多相机） | 负集失真、打分随机 | **所有相机全掩**；断言“看得到物体的那一路 ratio 才大” |
| 7 | clean LIBERO 无信号 | 无法直接发表 | 主战场放 SIMPLER / LIBERO-Plus 背景维度（`pcd.md` §9.5） |
| 8 | 滞回状态与异步预取错位 | 选出 chunk 与上一段接不上 | `_promote_next_chunk` 同步更新 incumbent；`skip_stale_actions` 按 chunk 而非按流水线 |

## 9. 建议的落地顺序

| 阶段 | 内容 | 估算 |
| :--- | :--- | :--- |
| M1 | **成本剖面先做**：`profile=True` 量三段占比，反推可行的 M | 0.5 天 |
| M2 | 方案 1 探针：重噪 m=2、M=4、配对 Δv + JerkRMS + 接缝 + 滞回；G1/G2/G3 通过 | 1 天 |
| M3 | 离线：候选排序相关度 + m=1→4 曲线（判断多样性是否为瓶颈） | 0.5 天 |
| M4 | 通道遮挡诊断（`pcd.md` §9.3），决定 grounding 是否值得做 | 0.5 天 |
| M5 | 若 M3 显示多样性是瓶颈 → 升级方案 2（buffer 加 M 维、mask 换 `_build_shared_obs_mask`），复用方案 1 的打分器 | 1 天 |
| M6 | 对照臂 + 分层评测（SIMPLER / LIBERO-Plus 背景维度），5 seeds | 算力 |

### 决策树

1. **m=2 无信号、m=4 有信号** → 多样性是瓶颈 → 上方案 2。
2. **m=2 与 m=4 无差别** → 信号不在路径上，问题在判据而非架构，不必扩 buffer。
3. **m=2 完全没信号** → 先跑 §7.1 G4 通道诊断，确认 grounding 通道是否有空间，否则任何候选选择都是无信号噪声。
4. **M=4 的 G3 不过** → 降到 M=2，或只做 JerkRMS + 接缝（零额外算力），或退回 `pcd.md` 的单步对比。

## 10. 明确不做的事

1. **不做“用槽 1/2/3 补足当候选”**：目标时刻不同、成熟度不等，不可比（§1.2）。
2. **不做“偶尔做 M 路”**：M 条流水线必须每步推进才能同步，只能整段固定 M。
3. **不在读出时跑全 ODE 作为主方案**：候选只条件在当前观测上，增益易被“新鲜观测”混淆（仅作对照臂）。
4. **不开 dropout 造多样性**：推理期未按此训练，噪声统计不受控。
5. **不照抄 SDN 的 kNN**（单 buffer 时）与 **JerkRMS 单项**（流式时）：前者前提失效，后者漏掉接缝。

## 11. 三个可选的更强变体（暂不进入主路径）

| 变体 | 做法 | 评价 |
| :--- | :--- | :--- |
| **尾部准入筛选（cascade）** | 在噪声入口用一步粗估（$a\approx\varepsilon-v(x_1,1)$）筛 k 个种子，只放 M 个进流水线 | 最省（k=16、M=4 时约 320 token），但 $t=1$ 处观测信息最少，**必须先做 Spearman 相关度研究** |
| **中段剪枝（beam）** | 在 slot 1 剪掉一半，成本约 0.75× | 剪枝后要用新噪声补位，破坏“M 条同步”不变量，复杂度/收益比不划算 |
| **候选分歧作运行时信号** | 用 M 条流水线的 std 或 Δv 离散度驱动 `async_manager` 的 `overlap_steps` | **不需要掩码、不需 2× prefix**；即使 grounding 测不出效果也能独立成文，与主路径并行 |

---

## 12. 一句话总结

> **候选要来自“多条流水线的同一时刻”，而不是“同一条流水线的多个时刻”。**
> 方案 1 成本低但结构上只治抖动与接缝；方案 2 能拿到 SDN 的真实收益但受 overlap 窗口约束。
> 真正的闸门是 G3（成本）与接缝项（指标可信度），不是显存。
