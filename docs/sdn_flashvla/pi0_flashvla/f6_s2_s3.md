## 0. 方案级修正：π0\* 的 proprio 与 action **共享权重**

早期方案（S1 的「独立第三路 311M 栈」）基于一个错误的源码事实。实际是：

```python
# third_party/SDN/simpler_env/policies/pizero/open_pi_zero/src/model/vla/pizero.py:274-276
def tie_action_proprio_weights(self):
    """technically more than just tying weights"""
    self.joint_model.mixtures["proprio"] = self.joint_model.mixtures["action"]
# 调用点：pizero.py:894    model.tie_action_proprio_weights()
# 旁证：pizero.py:123  "# note: action and proprio share weights"
#       pizero.py:335  "since proprio and action share the same mixture weights, ..."
```

数据侧证实（两份官方 ckpt 都是）：

| ckpt | proprio == action | 同一 storage | `proprio_encoder` |
| :--- | :---: | :---: | :--- |
| `bridge_beta_step19296...` | True（逐位） | True | `(1024, 7)` |
| `fractal_beta_step29576...` | True（逐位） | True | `(1024, 8)` |

即 `.pt` 里 165 个 `mixtures.proprio.*` 是 action 栈的**重复序列化**（连 `mixtures.*.norm.weight` 都一样）。
**唯一 proprio 专有的是 `proprio_encoder`。**

因此 S2 的实现语义是：**proprio block 复用 action expert 的 attention / MLP / norm 权重**，
三路只多 `proprio_in_proj`（1024×8 + bias ≈ 8.2 K 参数，+0.02 MB）。

## 1. S2 施工单（训练前向）

### 1.1 `modeling_pi0.py`：融合层支持「同一个权重跑两遍」

| 改动 | 落点 |
| :--- | :--- |
| `PI0Attention.__init__(..., share_proprio: bool = False)`；`_stream_attentions()` 返回 `[vlm, action, action]`（**同一对象两次，且不注册第二份**，否则 state_dict 会出现重复 key → safetensors 拒绝保存） | `PI0Attention` |
| `_as_three()` / `_pack_streams()` / `_unpack_streams()`：按块重交错，见 §1.2 | 同上 |
| `PI0MLP.__init__(..., share_proprio)`；`_stream_mlps()` 同样返回 `[vlm, action, action]` | `PI0MLP` |
| `PI0ModelLayer.__init__(..., share_proprio)`；`num_streams = 3 if share_proprio else 2`；`input_layernorm` 始终只有 2 项，第三个流经 `_norm_at()` 复用到 action 那一份 | `PI0ModelLayer` |
| 三处长度断言：`PI0Attention` / `PI0MLP` / `PI0ModelLayer` 在 `len(hidden_states)` 与模块数不符时 `raise`（替代原来被 `zip()` 静默截断的行为） | 同上 |

`share_proprio=False` 时走的代码与改动前逐字节等价（见 §3.3 守恒证据）。

### 1.2 关键：重交错必须在 `PI0Attention` 内部做

真实 suffix 布局是 **N 个块，每块 `1 + N*C` 个 token**：

- `H_cfg = N*C`，`x_t` 共 `N*H_cfg` 个 action token，`x_t_flat = x_t.view(B*N, H_cfg, -1)`（`modeling_pi0_flashvla.py:520`）→ 每行都是 `[state, 全部 N*C 个 action]`；
- `suffix_embs = embs_flat.view(B, N, L_suf, -1)`（`:533`，`L_suf = 1 + N*C`）→ 序列 = `[pro_0, act(0…N*C-1), pro_1, act(0…N*C-1), …]`；
- mask 侧用 `offset_ids = suffix_positions // L_suf`（`utils.py:335-341`）做块对角屏蔽。

所以三路 QKV 之后不能直接 `cat([vlm, pro, act])`，必须

```python
# PI0Attention._pack_streams: q/k/v 是 [B, heads, seq, head_dim]
per_block = action.shape[2] // num_blocks              # = N*C
suffix = cat([proprio.unsqueeze(3), action.view(B, H, N, per_block, Dh)], dim=3)
suffix = suffix.reshape(B, H, N * (per_block + 1), Dh)  # 与 mask 的顺序一致
```

输出再按同样的块结构解回三份（`_unpack_streams`），各自过自己的 `o_proj`。
**mask / position_ids 一个字都没改。**

### 1.3 `modeling_pi0_flashvla.py`：接线

| 改动 | 说明 |
| :--- | :--- |
| `PI0SuffixEmbedder.project_state()` | `use_proprio_stack` 时用 `proprio_in_proj(state[..., :proprio_input_dim])`，否则 `state_proj(state)`；`state` 是被 `pad_vector` 右补到 32 维的，必须切片 |
| `_split_suffix_streams()` | 按 `block_len = 1 + N*C` 切出 `action` 与 `state`；断言 `tokens % block_len == 0` |
| `_suffix_hidden_states()` | 返回 `([action_embs, state_embs], [cond, None])`；两路时返回 `([suffix_embs], [cond])` |
| `_empty_prefix_streams()` | prefill 时占位：两路 `[None]` / 三路 `[None, None]` |
| `self.use_proprio_stack` | 模型级标志；`state_proj.requires_grad_(False)`；`use_adarms_time_cond=true` 时显式 `raise` |
| 删除 `_require_proprio_forward()` | 由 §1.1 的长度断言取代 |
| 删除 `proprio_expert` | 连带删除 `detach_backbone_layer_aliases` / `to_bfloat16_for_selected_params` / `init_{qkv,mlp}_fusion_from_existing` / `fsdp_*_name_suffixes` / `prepare_for_fsdp` 里的第三路分支 |

训练前向末尾：`action_out` 直接取 action 流（三路时不再需要 `[:, :, 1:, :]` 去切 state token）；
proprio 流输出**丢弃**（π0\* 里也没有任何东西解码它）。

### 1.4 `train.py`：`state_path_lr_mult` 覆盖 `proprio_in_proj`

```python
state_ids = {id(p) for n, p in policy.named_parameters()
             if ".suffix_embedder.state_" in n or ".suffix_embedder.proprio_in_proj" in n}
```
理由：S0-B 臂里编码器装在 `state_proj` 上、吃了 3× lr；三路下同一个编码器搬到 `proprio_in_proj`，
若不覆盖，S5 的「臂③ vs S0-B」就变成两个变量。

### 1.5 转换器 `convert_pi0star.py`

`--emit-proprio-stack` 的新语义：**只**产出 `proprio_in_proj`，把 165 个 `mixtures.proprio.*` 全部丢弃
（它们是 action 栈的副本），`state_proj` 置零并标注为 inert；不再合成 `proprio_expert.*`。

```bash
env -u PYTHONPATH -u BASH_ENV HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  <env>/bin/python scripts/p4/convert_pi0star.py \

  --data /data/zjr/simpler_lerobot/fractal/google_robot_close_drawer/success \
  --empty-cameras 0 --write --dst ckpt/pi0star_fractal_flashvla_proprio_stack \
  --emit-proprio-stack --proprio-layout flashvla_quat \
  --json logs/p4/convert_fractal_proprio_stack_write.json
```

## 2. S3 施工单（三条推理路径）

| 路径 | 改动 |
| :--- | :--- |
| `denoise_step` | `hidden_states = [None, *self._suffix_hidden_states(...)]`；末尾不再切 state token |
| `_cold_start` / `_steady_streaming` | prefill 用 `[prefix_embs, *self._empty_prefix_streams()]`，三路时是 `[prefix, None, None]` |

单步 suffix 只有一个块（`buf_len = N*C`，`L_suf = 1+buf_len`），`_split_suffix_streams` 自然得到
`pro_num = 1`，与训练侧的 `pro_num = N` 共用同一段代码。

回归约束：`use_proprio_stack=false` 的老 ckpt 用新代码跑 `probe_actions.py` 必须**逐位不变**。

### 3.7 操作陷阱（踩过）

- `train/train.sh` 用裸 `python`，必须把 `<env>/bin` 放到 `PATH` 最前，否则会落到系统的
  `/home/zjr/miniconda3/lib/python3.4`（一个 `SyntaxError` 现场）。
- `PI0FlashVLAConfig.from_pretrained()` 不接受 `config.json` 里的 `type` 字段，读配置要走
  `PreTrainedConfig.from_pretrained(...)`。
- 两个 ckpt（含 `runs/f6_s2_*`）都落盘在工作区内；`output_dir` 必须是全新目录，否则 `auto_resume` 接管。
