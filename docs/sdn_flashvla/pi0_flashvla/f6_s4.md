## 0.1 目标（原封不动）

让 bridge 也能用上 π0\* 的 proprio 先验。fractal 已经通了（8 维四元数，`--proprio-layout flashvla_quat`），
bridge 不行：π0\* 侧的 proprio 是 **7 维 `POS_EULER`**，我们是 8 维四元数 state。

## 0.2 方案级修正：原文档的「归一化先按现状跑」**做不到**

原文 §归一化口径 写「π0\* 的 proprio 归一化 vs 我们的 `QUANTILES`：先按现状跑」。
实测发现这条路是死的，两个原因：

1. **quat→euler 是非线性变换**，必须在归一化**之前**做。若先按 8 维统计量归一化再转，
   得到的四元数已不是单位四元数（`quat2mat` 会输出非正交矩阵），欧拉角是垃圾。
2. 现有 `QUANTILES` 的 `observation.state` 统计量是 **8 维**（`q01/q99` 形状 `(8,)`），
   而转换后是 7 维 → `NormalizerProcessorStep._apply_transform` 的广播直接报错
   （`normalize_processor.py:362-378`）。

所以「按现状跑」实际含义只能是：**口径（QUANTILES）不动，为 7 维新造一套统计量**。
本次即按此施工，并把「用 π0\* 自己的 p01/p99」作为备选一并产出（见 §2.3），供后续单独成臂。

## 1. 唯一不能猜的地方：7 维到底是什么

已从源码确认（不再有任何猜测）：

```python
# third_party/SDN/simpler_env/policies/pizero/simpler_adapter.py:179-192
def preprocess_proprio(self, proprio):
    rm_bridge = quat2mat(proprio[3:7])                      # w 在前
    rpy_bridge_converted = mat2euler(rm_bridge @ self.default_rot.T)   # axes="sxyz"，弧度
    gripper_openness = proprio[7]
    raw_proprio = np.concatenate([proprio[:3], rpy_bridge_converted, [gripper_openness]])
# default_rot（:172-174）= [[0,0,1],[0,1,0],[-1,0,0]]，bridge 的 EEF 是 top-down 系
```

| 事实 | 出处 |
| :--- | :--- |
| 7 维 = `[x, y, z, roll, pitch, yaw, grip]`，xyz 原样、rpy 弧度、grip 是**开度**（0 关 1 开，与我们同向） | `simpler_adapter.py:179-192` |
| `mat2euler` 默认 `axes="sxyz"`，即 `roll=atan2(M21,M22)`、`pitch=atan2(-M20,cy)`、`yaw=atan2(M10,M00)` | `open_pi_zero/src/utils/geometry.py:49-115` |
| 我们的 state = `[x, y, z, qw, qx, qy, qz, grip]`（同样 w 在前、同样是开度） | `sim_eval/simpler/convert_simpler_to_lerobot.py:55` |
| `proprio_encoder` 形状 `(1024, 7)` | `.pt` 张量清点；转换报告 `proprio_in_proj.source=[1024,7]` |
| 归一化是 `bound`：`2(x-p01)/(p99-p01)-1` 再 clip 到 `[-1,1]` | `simpler_adapter.py:81-95`、`open_pi_zero/src/agent/env_adapter/base.py:17-18` |

**与 fractal 的关键差别**：fractal 的 8 维不匹配是纯置换 + 夹爪取反，可以折进编码器的
权重（`--proprio-layout flashvla_quat`）；bridge 的 8→7 是**非线性降维**，只能改数据。

### 2.1 为什么 step 必须排在 Normalizer 之前

管线顺序（`processor.py`）：

```text
Rename → AddBatchDimension → [ProprioLayout(bridge_euler7)] → Normalizer(7 维统计量) → 语言 → tokenizer → device
```

`ProprioLayout` 之后 state 是 7 维、raw 尺度；`Normalizer` 用 `state_stats_path` 的 `q01/q99`
把它压到 `[-1,1]`。**归一化仍然只发生在 `NormalizerProcessorStep` 里一处**，没有第二份实现。

### 2.2 统计量注入的持久化路径（已实测）

训练时 `train.py:887` 同时传 `pretrained_path` 与 `dataset_stats`，因此 `make_pre_post_processors`
走「按配置现场构建」分支（`factory.py:190` 的 `dataset_stats is None` 才读盘）。7 维统计量在
这里被注入 `Normalizer`，随后由 `PolicyProcessorPipeline.save_pretrained` 写进 ckpt 的
`policy_preprocessor.json` + step `state_dict`。推理期 `make_pre_post_processors(pretrained_path=ckpt)`
（`dataset_stats=None`）从 ckpt 读回，**不需要**再知道 `state_stats_path`。

### 2.3 两套 7 维统计量（本次用 A，B 留作后续臂）

| 套 | 文件 | q01/q99 来源 | 口径 |

| B（备查） | `logs/p4/f6_s4_bridge_state7_pi0bound.json` | π0\* `bridge_statistics.json` 的 `proprio.p01/p99`（全量 2,195,527 帧） | 等价于 openpi 的 `bound`，与预训练编码器的训练分布完全一致 |

两者差多少（各维 `q99-q01` 之比 A/B）：

## 4. 遗留与后续

1. **没有 2 步两路 bridge 对照**：所以 §3.4 的 loss 只能自证「有限、量级合理」。若将来要对
   bridge 做 proprio 臂的 A/B，需要补一条只差 `use_proprio_stack` 的两路 baseline。
2. **没跑 bridge 的探针**：S4 的验收止于 shape/数值/前向；bridge 三路的价值判定属于 S5 的
   同构问题（fractal 上先做），不在本阶段。
3. **统计量口径 B 未跑**：`state_stats_path` 换成 `..._pi0bound.json` 即得「与预训练编码器同分布」
   的臂，但目前**没有**任何训练证据说明 A 与 B 谁更好，按「不在同一臂里同时改归一化和架构」
   的纪律单独成臂。
4. **grip 维的 q99 == 1.0**：该 leaf 的夹爪开度 99 分位就是 1.0，归一化把 `x=1` 映到 `+1`
   （不 clip 也不会越界）；若换到 grip 更连续的数据集，`q99<1`，上界会留余量，无需改动。
