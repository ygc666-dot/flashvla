## 0. 一页结论

1. π0\* 的「三路 mixture」不是复杂交叉注意力，而是**一条因果序列上的三个 token block**：
   `[vlm 2048] → [proprio 1 token 1024] → [action 4 token 1024]`（`joint_model.py:448-469`）。
2. **proprio block 与 action block 共用同一组权重**（`pizero.py:274-276` 的 `tie_action_proprio_weights()`，
   调用点 `:894`）。π0\* 侧真正 proprio 专有的只有一个 **输入编码器** `proprio_encoder`（`(1024,8)` fractal / `(1024,7)` bridge）。
   → 三路相对两路只多 `proprio_in_proj`（≈8.2 K 参数），**不是** 311M 的第三套 decoder。
3. FlashVLA 现在的 suffix 布局已经与它同构：每个 buffer 配置的 suffix 首位就是一个 state token，
   `att_mask=1` 自成 block（`modeling_pi0_flashvla.py:205-222`），**mask / position 无需重写**。
   F6 的全部工作是「把这一个 token 的 QKV / norm / MLP 交给同一组 action 权重，并用 π0\* 的编码器产出它」。
4. S0 结论：`proprio_encoder` 装进 `state_proj` 后 2000 步 A/B 在 6/6 运动维 + 夹爪上全面更优
   （`mae 0.1361 → 0.1225`）；`corr(dx)` 只 +0.023，未达 +0.05 阈值，但两臂该指标都还在 0 附近，无分辨力。
5. S2/S3 结论：三路融合已落地，两路路径**逐位守恒**（CPU fp32 与 GPU bf16 的 `max|diff| = 0`），
   老 ckpt 的探针数字**逐位不变**（`mae_overall` 差 0.0），三路 smoke loss 与两路同量级（1.459/1.478 vs 1.435/1.488）。
6. S4 结论：bridge 的 7 维 `POS_EULER` 口径已落地，与 π0\* 参考实现**逐元素 `max|Δ| = 4.44e-16`**
   （阈值 1e-6）；bridge 三路 ckpt `verify.ok=true`，2 步 smoke loss 有限、`state_path_lr_mult`
   命中 4 张量，ckpt 自己的 preprocessor 把真实 8 维帧转成 7 维并归一到 `[-0.86, +1.12]`。
   **方案级修正**：原「归一化先按现状跑」不可行（quat→euler 非线性、8 维统计量喂 7 维会报错），
   实际做法是「QUANTILES 口径不动 + 为 7 维新造统计量」。
7. S5 结论（**GO，但归因反转**）：③（三路 + π0\* 编码器）相对 ①（两路 + 编码器装 `state_proj`）
   **6/6 运动维 + 夹爪全胜**，`mae_overall 0.12254 → 0.10343`（−15.6%），`corr(dx) −0.021 → +0.110`
   （+0.131，阈值 +0.05），夹爪二分类 0.7708 → 0.8229。
   但 ②（三路 + **随机**编码器）比 ① 更差（运动维 +11.8%，6 维只赢 1 维）→ **「多一个 block」本身
   没有价值，价值全在 π0\* 编码器的方向上**。这是对 §1 里「只多 8.2 K 参数因此几乎免费」的直接否定。
8. 副产品：三个臂的 state 输入投影在 2000 步里位移都在同一量级（`cos ≈ 0.9995`），说明
   `f6_s0_s1.md` §7.4 的「用 O(0.1) 初始化解锁 Adafactor」在机制上不成立（相对步长与参数 RMS 无关）。
9. 下一步：臂③ 8000 步长跑（唯一被支持的路线）；bridge 上按「预训练编码器 vs 不用」做同构 A/B。

## 1. 已确认的源码事实（施工依据，勿再猜）

| 事实 | 出处 |
| :--- | :--- |
| π0\* 序列顺序 `[vlm][proprio][action]`；proprio 只看 vlm+自己，action 看 vlm+proprio+自己 | `third_party/SDN/simpler_env/policies/pizero/open_pi_zero/src/model/vla/joint_model.py:448-469` |
| **proprio mixture 与 action mixture 共享权重**（`mixtures["proprio"] = mixtures["action"]`） | `pizero.py:274-276`，调用点 `:894`；`.pt` 里两者逐位相同且同一 storage |

| proprio **专有**的只有输入编码器：fractal `(1024,8)`、bridge `(1024,7)`，各带 bias | `.pt` 张量清点 |
| `num_proprio_tokens = cond_steps = 1`；`horizon_steps = 4` 与 `chunk_size=4` 一致 | `pizero.py:51`；`config/eval/{bridge,fractal}.yaml:21-22` |

## 4. 风险与回退

| 风险 | 缓解 / 现状 |
| :--- | :--- |
| 三路融合的 mask/position 隐蔽错误 | 已用 `_pack_streams` 重交错 + 三层长度断言 + golden 逐位比对 + 等价单测挡住（`f6_s2_s3.md` §3） |
| `use_proprio_stack=false` 被改坏 | golden（CPU fp32 / GPU bf16）与老 ckpt 探针均**逐位不变** |
| state_dict 出现重复 key（共享权重写错） | `_stream_attentions()` 返回同一对象两次但只注册一份；转换器 `verify.ok` 与单测 `extra == [in_proj.w, in_proj.b]` 双向把关 |
| state 输入投影在 Adafactor 下几乎不更新 | **已量化**（`f6_s5.md` §3.4）：三臂在 2000 步里 `cos ≈ 0.9995`、rms 变化 <0.05%。`f6_s0_s1.md` §7.4 的「用 O(0.1) 尺度」**在机制上无效**（相对步长与参数 RMS 无关），要解锁只能换优化器/单独 lr 组 |
| 把「随机初始化的 proprio 通路」当中性对照 | **已被否**（`f6_s5.md` §3.3）：臂② 比臂① 差 11.8%，随机投影在共享权重下是有害偏置。任何三路对照必须两边都用预训练编码器 |
| 显存 | 三路仅 +8.2 K 参数；实测峰值 8.20 GiB（bs1 推理）/ smoke bs4 无异常 |
| S0 NO-GO 被误读成「proprio 通路无用」 | S0 只覆盖输入编码器；block 本身的价值要 S5 的 ②③ 才能分离 |
| FSDP2 | 三路不再新增 decoder 参数，`detach_backbone_layer_aliases` 无需第三路分支；仍先单卡跑通 |

## 5. 明确不要做的事

1. **不要**在同一臂里同时改归一化/掩码和架构（A/B 失去归因）。
2. **不要**用绝对 loss 跨臂比较（口径地板不同，见 §1）。
3. **不要**在 S5 之前跑 M=1 评测（50 seeds 的 SE≈3.5 pp，只会浪费钱）。
4. **不要**给 proprio block 单独一套 decoder 权重（π0\* 是共享的；那会引入 π0\* 不存在的自由度）。
5. **不要**删 `state_proj`：它是 `use_proprio_stack=false` 的回退路径，老 ckpt 都依赖它。
6. **不要**在 `PI0Attention` 里直接 `cat([vlm, pro, act])`：suffix 是 `[pro_n, act_n…]` 分块交错，必须按块重交错。
7. **不要**把 proprio 通路接一个随机编码器再和「不用 proprio」对比（`f6_s5.md` §3.3 已证明它有害）。
8. **不要**在归一化**之后**做布局转换（quat→euler 是非线性的，必须排在 `NormalizerProcessorStep` 之前，见 `f6_s4.md` §2.1）。
