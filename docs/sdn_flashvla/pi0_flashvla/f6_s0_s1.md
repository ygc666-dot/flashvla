### 7.1 修正一：π0\* fractal 的 proprio 与我们的 state **不同序**

`f6.md` 早期版本称 fractal 的 `POS_QUAT` 8 维「与我们 8 维四元数 state 同构」——**只同形，不同序**：

```python
# third_party/SDN/simpler_env/policies/pizero/simpler_adapter.py:222-235
# (EDRSimplerAdapter.preprocess_proprio，fractal 用的就是它)
quat_xyzw = np.roll(proprio[3:7], -1)        # wxyz -> xyzw
gripper_closedness = 1 - gripper_width        # openness -> closedness
raw_proprio = concat([proprio[:3], quat_xyzw, [gripper_closedness]])
```

```55:56:flashvla/sim_eval/simpler/convert_simpler_to_lerobot.py
STATE_NAMES = ["x", "y", "z", "qw", "qx", "qy", "qz", "gripper"]
```

即 π0\* = `[x,y,z,qx,qy,qz,qw,1-grip]`，我们 = `[x,y,z,qw,qx,qy,qz,grip]`，**8 维里错 5 维**。
数据侧旁证：我们的 grip 是 openness（min .168 / max 1.0），`1-0.61=0.39` 对上 π0\* `fractal_statistics.json`
的 proprio[7] mean `.4261` / range `[0,1]`。

修法（`convert_pi0star.py` 新增 `--proprio-layout flashvla_quat`，**纯转换器、零框架改动**）：

```python
PROPRIO_TO_STATE_PERM = (0, 1, 2, 6, 3, 4, 5, 7)
PROPRIO_TO_STATE_SIGN = (1, 1, 1, 1, 1, 1, 1, -1)
aligned = W[:, perm] * sign
aligned_bias = b + W[:, 7]      # 1-grip 的常数项折进 bias
```

数值自检：`|W@p+b − (W'@s+b')| = 2.4e-7`（float32 舍入级）。

> **S4 的 bridge 未被这个修法覆盖**：bridge 是 7 维 `POS_EULER`，维度就不同，
> `_align_proprio_encoder` 会显式报错而不是静默截断。见 `f6_s4.md`。

### 7.4 新发现：Adafactor 让 `state_proj = N(0,1e-3)` 结构性冻结

训练完两臂的 `state_proj` 实测（`002000/pretrained_model/model.safetensors`）：

| 臂 | 权重 rms | bias rms | 结论 |
| :--- | ---: | ---: | :--- |
| A（init `N(0,1e-3)`） | 1.0020e-3（init 1.0031e-3） | 5e-5 | **2000 步几乎没动**，state 通路等同死路 |
| B（init `proprio_encoder`） | 0.1023（init 0.2044） | 0.2833 | 有量级、在适配 |

- 这是在 `state_path_lr_mult: 3.0` **确实生效**（日志 `base_lrs=['5e-05', '0.00015']`）的前提下发生的。
- 机理：Adafactor 用参数自身 RMS 做相对步长，1e-3 量级参数的步长被相对化到同比例 → 等于冻结。
- 推论：**「小随机初始化 + lr×3」救不活 state 通路**；要给它真机会，必须把初始化放到 **O(0.1)** 量级。
- 这也是 B 臂能全维领先的**结构性原因**：只有 B 的 state 通道有非零量级。

> **2026-11-24 修正（S5 §3.4）**：上表有两处需修正，原始结论「把尺度提到 O(0.1) 就能解锁」**不成立**。
> 1. **A/B 两行的 rms 不同口径**：B 的 `state_proj` 是 `_pad_cols(encoder)` 到 32 列（后 24 列补零），
>    0.2044 是只按 8 个真实列算的，0.1023 是按 32 列算的。换算到同一口径后 B 是 **0.1022 → 0.1023**，
>    即 B 也几乎没动，原「B 在适配」不成立。
> 2. **机理的推论错在方向**：torch `Adafactor`（`_adafactor.py:395-415`）的 `alpha = max(eps2, RMS(p))·rho_t`，
>    于是**相对**步长 `= rho_t · RMS(update)/max(1, RMS(update)/d)`，与参数自身 RMS **无关**。
>    所以 init 尺度只同比例放大「能走的绝对距离」，不改变相对学习率——A 换成 0.1 仍会几乎不动。
>    要解锁只能换优化器（AdamW）或给该张量单独放大 lr，属于另一个臂。
