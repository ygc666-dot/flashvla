## 1. 为什么必须跨进程

两侧的环境互斥，任一方向的合并都会破坏现有可用栈：

| 依赖 | `sdn`（SIMPLER） | `flashvla`（训练/推理） |
| :--- | :--- | :--- |
| Python | 3.10.22 | 3.12.16 |
| torch | 2.3.1+cu118 | 2.9.1+cu128 |
| transformers | 4.44.2（`groundingdino==0.1.0` 锁定） | 5.3.0（`lerobot.policies.pi_gemma` 需要） |
| 关键包 | sapien 2.2.2、mani-skill2-real2sim 0.5.3、numpy 1.24.4 | lerobot 0.5.1、numpy 2.x |

不能做的两件事：

1. **往 `sdn` 里装 lerobot/torch2.9** —— 该环境正在 GPU4 上跑 SDN 评测，且 `transformers` 4.44.2 与 5.3.0
   只能活一个（`2.md` §6.2 已给出结论：「不要共存」）；
2. **往 `flashvla` 里装 sapien** —— sapien 2.2.2 无 cp312 wheel（`2.md` §6.2）。

因此采用 `2.md` §6.1 的**跨进程 server**：权重与推理留在 `flashvla` 进程，环境与渲染留在 `sdn` 进程，
两者只交换 `(image, state, instruction) → delta action`。

```
 [flashvla env, py3.12]                    [sdn env, py3.10]
  pi05_server.py  ◀──── TCP :12345 ────▶  simpler_client_eval.py
  ├ load ckpt (4.14B)                       ├ simpler_env.make(task)
  ├ pre: normalize+tokenize                 ├ env.reset(seed=ep)
  ├ predict_action_chunk (10-step ODE)      ├ env.step(...) × 4
  └ post: unnormalize (+可选重标定)          └ 记录 success / first_success
```

**代价**：无法测 overlap / 端到端延迟（TCP + 进程切换）。但 P0 只问成功率，M=1 闸门也只问成功率，
不影响结论；正式的性能数字留给 P4 的 py3.10 统一环境。

## 2. 实现结构

### 2.1 server：`scripts/p0/pi05_server.py`

加载链路（`main`）：

```python
cfg = PreTrainedConfig.from_pretrained(args.ckpt)   # 注意：不是 PI05Config.from_pretrained
cfg.compile_model = False
policy = PI05Policy.from_pretrained(args.ckpt, config=cfg)
pre, post = make_pre_post_processors(cfg, pretrained_path=args.ckpt)
```

每次请求的 5 步处理链：

| 步 | 动作 | 备注 |
| :- | :--- | :--- |
| 1 | `torch.manual_seed(seed*100000 + n_calls*7919)` | 让初始噪声随 episode 可复现 |
| 2 | `build_batch()`：`bytes → uint8 → /255 → [1,3,H,W]` | 传原始分辨率，resize 交给模型内 `prepare_images` |
| 3 | `pre(batch)` + `state.clamp(-1,1)` | 见 §3.6 |
| 4 | `policy.predict_action_chunk(batch)` | 返回 `[1, 50, 7]`（`n_action_steps=50`） |
| 5 | `post(chunk)[0, :exec_steps, :7]` → 可选重标定 → `tolist()` | 只回传接下来要执行的 4 步 |

**参数表**：

| 参数 | 默认 | 作用 |
| :--- | :--- | :--- |
| `--ckpt` | `ckpt/pi05_libero` | 任意 FlashVLA/pi05 目录 |
| `--exec-steps` | 4 | 每次请求返回的动作数（对齐 π0\* 的 `act_steps=4`） |
| `--no-dup-view` | off | 默认把单相机复制给第二个视角槽（乐观设置，见 §3.5） |
| `--clip-state` | 1.0 | 归一化后 state 裁到 `[-1,1]` 再离散化，`<=0` 关闭 |
| `--clip-action` | 0（关） | 输出 delta 裁剪 |
| `--rescale-stats` | off | 用 SIMPLER 的逐维 `mean/std` 重新表达输出（公平对照，见 §3.7） |

### 2.2 client：`scripts/p0/simpler_client_eval.py`

主循环刻意与 `third_party/SDN/policy/pizero/evaluate.py:188-262` 对齐，保证与 R1 的
`results.md` 数字可比：

| 项 | 实现 | 对应 SDN 原始代码 |
| :--- | :--- | :--- |
| 场景重建 | `env.reset(seed=ep, options=dict(reconfigure=True))` | `evaluate.py:190` |
| 相机选择 | google→`overhead_camera`，widowx→`3rd_view_camera` | `evaluate.py:43-51` |
| proprio | `obs['agent']['eef_pos']`，8 维 | `evaluate.py:211` |
| 动作拼接 | `[world_vector(3), rot_axangle(3), gripper(1)]` | `evaluate.py:226-227` |
| 成功口径 | `info['success']` 任一步为真即成功，记首个 True 的步号 | `eval_utils.py:21-56` |
| 终止 | 只在 `truncated`（TimeLimit）退出，**不因成功提前终止** | `evaluate.py:210` |
| 指令 | 每步检查 `get_language_instruction()` 是否变化 | `evaluate.py:243-245` |

**与原始实现的唯一差异（有意为之）**：每 4 个环境步就用最新观测重新请求一次（不缓存 50 步 chunk），
以对齐 π0\* 的「每 4 步重推理」执行模式；否则对比会混入「用陈旧观测跑 50 步」的差异。

### 2.3 线上协议

长度前缀（4 字节大端）+ pickle，但**只允许纯 Python 对象**（见 §3.3）：

| 方向 | 字段 | 类型 |
| :--- | :--- | :--- |
| 请求 | `image` | `bytes`（uint8 HWC） |
| | `shape` | `tuple` |
| | `state` | `list[8]` |
| | `instruction` | `str` |
| | `seed` | `int` |
| | `domain` | `"fractal"` / `"bridge"`（供重标定选表） |
| 响应 | `actions` | `list[4][7]` |
| | `latency_ms` | `float` |

## 3. 七个坑与解法

按遇到顺序，每条都实际卡住过。

| # | 现象 | 原因 | 解法 |
| :- | :--- | :--- | :--- |
| 1 | `DecodingError: The fields 'type' are not valid for PI05Config` | ckpt 的 `config.json` 带 `type` 字段，draccus 解析子类时拒绝 | 用 `PreTrainedConfig.from_pretrained(path)`（它内部先 `pop("type")` 再按子类解析），不要用 `PI05Config.from_pretrained` |
| 2 | `httpx.ConnectError: Network is unreachable` | `TokenizerProcessorStep` 会去 HF 拉 `google/paligemma-3b-pt-224`，即使本地有缓存也会先联网 | 显式 `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1`（`2.md` §3.2 的老坑） |
| 3 | `ModuleNotFoundError: No module named 'numpy._core'` | `sdn` 是 numpy 1.24（`numpy.core`），`flashvla` 是 numpy 2.x（`numpy._core`），numpy 的 pickle 路径不兼容 | 协议里只传 `bytes`/`list`/`str`/`tuple`，不传 ndarray |
| 4 | 加载极慢 / 卡编译 | ckpt 里 `compile_model: true`，会触发 `torch.compile(max-autotune)` | 加载前 `cfg.compile_model = False`（`modeling_pi05.py:579-581` 是编译点） |
| 5 | ckpt 要两个视角，SIMPLER 只有一个 | `input_features` 是 `image` + `image2` + `empty_camera_0`；google 只有 `overhead_camera`，widowx 只有 `3rd_view_camera` | 把单相机复制给 `image2`（**乐观**设置）；`empty_camera_0` 由 `prepare_images` 自动补 mask=0（`modeling_pi05.py:1224-1252`） |
| 6 | 归一化后 state 最大值 **8.63**，远超 `[-1,1]` | `state_cond=False` 会把 state 按 `linspace(-1,1,257)` 离散成 256 桶，超界值全部塌进最后一个桶 | `--clip-state 1.0`，在离散化前裁剪（这是零样本下信息损失最小的处理） |
| 7 | 机械臂乱飞（80 步位移 0.68 m），全 0% | pi05 输出的是 **LIBERO 尺度**的 delta，SIMPLER 的动作尺度小 5–30 倍 | 见 §6 的重标定对照 |

## 4. 复现步骤

```bash
# ---------- 终端 1：server（flashvla env, GPU4） ----------
cd /home/zjr/workspace_tj/StreamingVLA/flashvla
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 CUDA_VISIBLE_DEVICES=4 \
  /home/zjr/workspace_tj/StreamingVLA/miniconda_ygc/envs/flashvla/bin/python \
  scripts/p0/pi05_server.py --ckpt ckpt/pi05_libero --port 12345 --exec-steps 4 --clip-state 1.0
# 约 145-150 s 加载完，打印 "[server] listening on 127.0.0.1:12345"

# ---------- 终端 2：client（sdn env） ----------
cd /home/zjr/workspace_tj/StreamingVLA/flashvla/third_party/SDN
for t in google_robot_close_drawer google_robot_move_near google_robot_open_drawer \
         google_robot_pick_coke_can google_robot_place_apple_in_closed_top_drawer \
         widowx_carrot_on_plate widowx_put_eggplant_in_basket \
         widowx_spoon_on_towel widowx_stack_cube; do
  CUDA_VISIBLE_DEVICES=4 /home/zjr/workspace_tj/StreamingVLA/miniconda_ygc/envs/sdn/bin/python \
    ../../scripts/p0/simpler_client_eval.py --task $t --n-episodes 5 --start-seed 100 \
    --port 12345 --out ../../results_p0/$t.json
done

# ---------- 重标定对照（server 需带 --rescale-stats 重启） ----------
CUDA_VISIBLE_DEVICES=4 ... python ../../scripts/p0/simpler_client_eval.py \
  --task google_robot_pick_coke_can --n-episodes 5 --start-seed 100 \
  --debug-actions --out ../../results_p0/rescaled_pick_coke_can.json
```

复现时注意三点：seeds **不要用 0-49**（那是 R1 的评测集，留作配对比较）；`--debug-actions`
会额外记录动作统计，用于区分「输出退化」与「域不匹配」；结束后 `pkill -f scripts/p0/pi05_server.py`
释放显存（约 8 GB）。

| 成功率 | 0/5 | **0/5** |

→ 尺度被修进合理量级，**仍然 0%**，说明失配不只是量纲。

## 6. 归因分析

两侧动作统计量［已核实，读 ckpt 的 `policy_preprocessor_step_2_normalizer_processor.safetensors`
与 `simpler_env/policies/pizero/open_pi_zero/config/{fractal,bridge}_statistics.json`］：

| 维度 | LIBERO ckpt `action.std` | fractal（Google Robot） | bridge（WidowX） | LIBERO/Simpler 倍率 |
| :--- | ---: | ---: | ---: | ---: |
| dx | 0.336 | 0.0692 | 0.0096 | 4.9× / 35× |
| dy | 0.378 | 0.0597 | 0.0135 | 6.3× / 28× |
| dz | 0.445 | 0.0735 | 0.0125 | 6.1× / 36× |
| rx | 0.039 | 0.156 | 0.028 | **0.25× / 1.4×** |
| rz | 0.078 | 0.146 | 0.076 | 0.53× / 1.03× |

两点结论：

1. **平移差 5–36 倍，旋转反而偏小** —— 说明两域的旋转增量语义不同（LIBERO 的 axis-angle 弧度 vs
   SIMPLER 归一化后的角度），单一全局缩放修不好，必须逐维 affine（`--rescale-stats` 做的就是这件事）。
2. **重标定后仍 0%** ⇒ 关键差距在**视觉域与机器人形态**：LIBERO 是桌面 Franka/Panda 的第三人称视角，
   SIMPLER 是 Google Robot 的 `overhead_camera` / WidowX 的 `3rd_view_camera`；加上单相机还要复制成
   第二视角。这类差距不能靠统计量或后处理弥补，只能靠**域内数据**。

这正是「teacher 必须是 π0\*」的实证依据：π0\* 的 `bridge_beta` / `fractal_beta` 是**域内**权重，
本机实测 67.3 / 68.7%（`../sdn/results.md`）。

## 7. 可复用点（直接服务 G3 / P4）

`scripts/p0/` 这两段不是一次性脚本，`3.flashvla_simpler.md` §6.1 的「跨进程 server（1–2 天）」已完成一半：

| 复用目标 | 需要改什么 | 工作量 |
| :--- | :--- | :--- |
| **G3：M=1 闸门** | `--ckpt` 换成训好的 `flashvla-pi05-simpler`；server 里 `PI05Policy` → FlashVLA 类（`predict_action_chunk` 接口一致）；client 无需改动 | 半天 |
| **P4：SDN 正式评测** | 同上，另需把 `predict_action_chunk` 换成 M 条流水线的读出侧选择（`1.md` §5）；若要测 overlap，仍得回到 py3.10 统一环境 | 2–3 天 |
| **调试任意 ckpt** | `--debug-actions` 已内置动作统计（std / 首末行 / 夹爪取值数 / EEF 位移），可当作通用的「策略是否在动」检查器 | 0 |
| **跨域统计量换算** | `load_rescale_tables()` 是通用工具：任意 ckpt 的输出都能用目标域的 `mean/std` 重新表达 | 0 |

**必须沿用**的一条经验：先跑 `--debug-actions` 单局，再跑批量。否则「全 0%」既可能是域问题，
也可能是某个静默的接口错位（本次就靠它排除了「输出退化」这一解释）。

## 8. 局限与未做的对照

| # | 局限 | 影响 | 若要补 |
| :- | :--- | :--- | :--- |
| 1 | 用 `ckpt/pi05_libero` 代替 `lerobot/pi05_base` | 结论方向更严（更强模型都 0%，基座只会更差），但严格说不是原设计的权重 | 拿到 `pi05_base` 后重跑同一命令 |
| 2 | 5 ep/任务 | 0/45 的 95% 上界约 8%，无法区分「0%」与「3%」 | 加到 50 ep/任务（≈1 h） |
| 3 | 第二视角用重复图（乐观） | 真实情况（空白视角）只会更差，不改变结论方向 | `--no-dup-view` 即可跑反向对照 |
| 4 | `state` clip 到 `[-1,1]` | 丢弃超界信息，但比全部塌进末桶更合理 | 换 `state_cond=True` 的 ckpt 可绕开离散化 |
| 5 | 噪声种子按 `(ep, call)` 派生 | 可复现，但与 π0\* 的采样器不同 | 无需补 |
| 6 | 未测「训练步数更多的 LIBERO ckpt」 | 与 P0 的问题无关（P0 问的是「能否直接用」） | 不补 |
| 7 | 未测端到端延迟 | 跨进程 + TCP，延迟无参考价值 | 留给 P4 的 py3.10 统一环境 |
