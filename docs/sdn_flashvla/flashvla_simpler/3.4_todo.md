```bash
#!/usr/bin/env bash
# scripts/p3/overnight.sh — 无人值守跑完 P0–P7；每个阶段幂等，可中断续跑
set -uo pipefail
cd "$(cd "$(dirname "$0")/../.." && pwd)"
LOG=logs/p3_overnight; mkdir -p "$LOG/gates"; PY=python
export CUDA_VISIBLE_DEVICES=4            # 全程只用 GPU4，不碰邻居卡
export CODEBUDDY_SAFE_DELETE_ENABLED=0
stage()  { echo "[$(date '+%m-%d %H:%M')] == $*" | tee -a "$LOG/main.log"; }
done_m() { test -f "$LOG/gates/$1.done"; }
mark()   { date > "$LOG/gates/$1.done"; }

stage P0 环境自检
# 代理三选一（直连→环境代理→7890 隧道），成功即 export 并继续
bash scripts/p3/probe_env.sh > "$LOG/P0_env.log" 2>&1 || { stage "P0 FAILED: 见 P0_env.log"; exit 1; }
mark P0

stage P1 下载 pi05_base（人在，看到稳定后再离开）
if [ ! -f ckpt/pi05_base/model.safetensors ]; then
  huggingface-cli download lerobot/pi05_base --local-dir ckpt/pi05_base \
      > "$LOG/P1_download.log" 2>&1 \
    || { stage "P1 失败：不回退，停在此处（见 P1_download.log）"; exit 1; }
fi
# 4 文件齐 + >7 GB 才继续；此处之后不再需要网络
for f in config.json model.safetensors policy_preprocessor.json policy_postprocessor.json; do
  test -s "ckpt/pi05_base/$f" || { stage "P1 缺 $f，停"; exit 1; }
done
mark P1

stage P2 T0 基线（9 任务，幂等）
bash scripts/p3/run_t0.sh > "$LOG/P2_t0.log" 2>&1   # 内部按 log 数跳过已完成任务
mark P2

stage P3 S0 冒烟门
bash scripts/p3/smoke_s0.sh > "$LOG/P3_s0.log" 2>&1 && mark P3 || stage "P3 失败→切 adafactor"
[ -f "$LOG/gates/P3.done" ] || bash scripts/p3/smoke_s0_adafactor.sh > "$LOG/P3_s0_adafactor.log" 2>&1 && mark P3

stage P4 S1–S4
bash scripts/p3/smoke_pipeline.sh > "$LOG/P4_smoke.log" 2>&1; mark P4

stage P5 S5 bs 扫描
bash scripts/p3/sweep_bs.sh > "$LOG/P5_sweep.log" 2>&1; mark P5

stage P6 起训练（gate 未过就不起；GPU4 已确认独占，只做一次显存断言）
if [ -f "$LOG/gates/P5.done" ] && grep -q '"trainable": true' "$LOG/gates/decision.json"; then
  FREE=$(nvidia-smi -i 4 --query-gpu=memory.free --format=csv,noheader,nounits | tr -d ' ')
  if [ "$FREE" -lt 40960 ]; then
    stage "P6 跳过：GPU4 free=${FREE}MiB < 40 GB，写报告、不等待"
  else
    bash scripts/p3/render_cfg.sh                     # 由 decision.json 渲染 _overnight.generated.yaml
    setsid nohup bash train/train.sh train/configs/pi05/simpler/_overnight.generated.yaml 1 \
        > "$LOG/P6_train.log" 2>&1 &
    echo $! > "$LOG/P6_train.pid"
  fi
fi

stage P7 报告
bash scripts/p3/make_report.py > "$LOG/P7_report.log" 2>&1
```

### 手动逐步执行（想分步做时看下面三节）

#### A 轨：下载 base 权重（本机走代理，人盯着）

```bash
cd /home/zjr/workspace_tj/StreamingVLA/flashvla
export HTTPS_PROXY=http://127.0.0.1:7890 HTTP_PROXY=http://127.0.0.1:7890   # 按你实际的代理方式
curl -I --max-time 10 https://huggingface.co          # 先确认通，再开始下载
huggingface-cli download lerobot/pi05_base --local-dir ckpt/pi05_base
du -sh ckpt/pi05_base && cat ckpt/pi05_base/config.json | head -3
```

- **必须是完整的 LeRobot policy 目录**，不能只要 `model.safetensors`：`policies/factory.py:191-205`
  会从**同一个目录**读 `policy_preprocessor.json` / `policy_postprocessor.json`，缺了会在建策略时报错。
- 体积参考：`ckpt/pi05_libero` 是 7.47 GB，base 应同量级（估算 7.5 GB）；`config.json` 的 `type` 应为 `pi05`。
- 下载稳定推进后即可离开，转入「通宵流水线」的 P2（`gates/P1.done` 会由编排器自己写）。
- 备查（**本次不启用**）：若最终拿不到 base，替代品是 `ckpt/pi05_libero`，代价是起点变成
  「LIBERO 先验 + SIMPLER 数据」，需在报告里显式声明。
- 风险：base 的 `input_features` 相机槽位可能与「1 真 + 2 空」不同 → **必须由 S2 断言**（缺键/多键在这一步暴露，
  不要等到 3 h 的正式训练里才发现）。

#### B 轨：占卡的 5 h（串行，先 T0 后冒烟）

1. **B1 = T0**（§3 的命令，纯推理，零代码改动，风险最低）。它同时产出 G3 的对照数，是后面所有判据的分母。
2. **B2 = 冒烟 S0–S5**（§4）。
3. 顺序理由：若 T0 就挂（渲染/权重路径），冒烟里的训练结果无从解释；而 T0 的 9 个 rate 无论训练成败都要用。

#### C 轨：优化器（不占卡，可在 B1 跑的 3 h 里做）

按成本从低到高，**前一步通过就停**：

1. **先试 `fsdp.enable: true` + `cpu_offload: true`（0 行代码）** —— `train.py:664-675` 只要
   `cfg.fsdp.enable` 就构造 plugin，没有 world_size>1 的前提，所以单进程也能开，把 30 GB Adam 状态放 CPU。
   这就是冒烟里的 **S0**，所以 C 轨第一步其实和 B2 的第一步是同一件事。
2. 若 accelerate 1.15 不接受 1 进程 FSDP → 注册 `adafactor`：在 `lerobot/optim/optimizers.py` 仿照
   `AdamWConfig`（`:100-113`）加 `@OptimizerConfig.register_subclass("adafactor")`，`build()` 里返回
   `torch.optim.Adafactor(params, lr=self.lr, ...)`（torch 2.9.1 自带，无需 bnb），配置写 `optimizer.type: adafactor`。
3. 可选加分项：把 `gradient_checkpointing` 接到 flashvla 的 pi05（照抄
   `lerobot/policies/pi05/modeling_pi05.py:491-495` 到 `flashvla/policies/pi05/modeling_pi05_flashvla.py`），
   激活再降一档，把 bs 推大。

验收统一为：单卡 `batch_size=2, steps=10` 不 OOM 且 loss 有限。

#### 这套方案**不**解决什么

| 不解决         | 说明                                                                                          |
| :------------- | :-------------------------------------------------------------------------------------------- |
| 显存缺口的本质 | C 轨只让「跑得动」，双卡 FSDP2 才是「跑得快」；GPU2 到位前正式训练仍是 40 h 级                |
| G3 评测入口    | `policy/pizero/evaluate.py` 目前加载不了 `pi05-flashvla` 目录，要另写适配器（不阻塞今天） |
| 数据侧         | P2 已收口，无需再动                                                                           |

   `observation.state [8]` / `action [7]` 与我们的数据集完全对齐）与 `ckpt/flashvla-pi05-libero`。
2. **优化器只有 `AdamWConfig` / `MultiAdamConfig` 等，没有 8-bit Adam / Adafactor**

   （`modeling_pi05.py` 里没有 `gradient_checkpointing_enable()` 调用）→ 不能靠它省激活。

## 1. 显存账：单卡 45 GB 为什么不够

以 3.74 B 全参 AdamW（bf16 训练）计：

| 项                                           |              大小 |
| :------------------------------------------- | ----------------: |
| bf16 权重                                    |            7.5 GB |
| bf16 梯度                                    |            7.5 GB |
| AdamW fp32 `exp_avg` + `exp_avg_sq`      |           29.9 GB |
| **固定开销小计**                       | **44.9 GB** |
| 激活（bs 2，256 token/帧，无 checkpointing） |          +3–6 GB |
| GPU4 空闲                                    |           45.4 GB |

**固定开销已经等于可用显存**，激活无处安放 → 单卡 bs≥1 全参 AdamW **必 OOM**。
即：`3.flashvla_simpler.md:330`「≥2 卡 FSDP2 是最低要求」这个判断是对的，我的实测印证了它。

三条降级路线（按推荐度）：

| 路线                                      | 显存                      | 代价                                                                                                              |
| :---------------------------------------- | :------------------------ | :---------------------------------------------------------------------------------------------------------------- |
| **A. GPU4+GPU2 双卡 FSDP2**（推荐） | 每 rank ≈ 22.5 GB + 激活 | 跨 NUMA `SYS` 通信，比 4 卡慢 2–3×；GPU2 邻居涨内存会被挤爆                                                   |
| B. 单卡 + `fsdp.cpu_offload: true`      | GPU 侧 ≈ 8 GB + 激活     | 每步 30 GB 优化器态 CPU↔GPU 往返，step 时间 ×2–3；**且需先验证 accelerate 是否允许 1 进程开 FSDP**（S0） |
| C. 冻结主体、只训 action expert / LoRA    | ≈ 10 GB                  | **改了实验定义**（不再是全参 FM 微调），需要你拍板                                                          |

## 2. 显存档位换算与时间估算（估算，S5 后校正）

单样本 fwd+bwd ≈ `6 × N × T` FLOPs，N=3.74 B。
假设 pi05 预处理把图像压到 **256×256**（3 个视觉槽 ≈ 780 token + 文本/状态/动作 ≈ 60 → T≈840）：

- 单样本 ≈ 18.9 TFLOP；L40S bf16 峰值 181 TFLOPS，MFU 35% ≈ 63 TFLOPS → **≈0.30 s/样本**。
- 等效 batch 32、12,000 步 = 384,000 样本 → **≈32 h 纯算**，取 80% 效率 ≈ **40 h（单卡）**；
  双卡按 1.7× 效率增益 ≈ **24 h**。
- bridge（4,000 步、等效 batch 32 = 128,000 样本）≈ 单卡 13 h / 双卡 8 h。

⚠️ **若预处理未把 512×640 缩到 256×256**（我们的 info.json 是 `(512,640,3)`），token 数涨到
≈1,700/帧，上述时间与激活都要 ×3–5，单卡基本不可行。**这正是 S4 必须验证的原因。**

## 6. G3 评测（每个 checkpoint ≈3 h，可放 GPU2 的 30 GB）

协议必须与 T0 完全一致（`--n-trajs 50 --start-seed 2000`，同任务集），否则 −2 pp 判据不成立。

- **缺口**：现有 harness（`policy/pizero/evaluate.py`）加载的是 open-pi-zero / SDN 系列 checkpoint

  推理时前 N−1 个槽是全 pad，与 `S=75` 有分布差，须在评测脚本里原样复现）。
- 判据：9 任务 macro ≥ π0\* − 2 pp；同时报 `apple`/`stack_cube` 两个精细任务的分项。
