## 0. TL;DR

**一句话方案**：用 **π0\***（`--method vanilla`）在 SIMPLER 9 任务上跑 rollout，每步落盘
`(image, proprio, action, instruction)`；按 `first_success` 截断、只留成功轨迹；转 LeRobot 后
用 **`pi05-flashvla`**（初始化 `lerobot/pi05_base`）做监督流匹配训练；M=1 过闸门后再接 SDN。

| 阶段 | 内容 | 卡 | 时间 | 验收闸门（可测） |
| :- | :--- | :--- | :--- | :--- |
| **P0** | teacher 判定：pi05 零样本 9×5 ep | 单卡 | **已跑完** | **G0 已判定：0/45 = 0.0%**（含重标定对照仍 0/5）→ teacher 必为 π0\*，跨架构路线成立（§2.1） |
| **P1** | 采数：dump 钩子 + `vanilla` 9 任务 | GPU4 | 1 天 + 12 h | **G1**：数据集体检（每任务成功 ≥50 条、帧数 ≥3k、重跑逐位一致） |
| **P2** | 数据工程：截断/筛选 → LeRobot → 统计量 | 无 | 2 天 | **G2**：`FlashVLADataset` 能出 `[N·H, 7]`；stats 对拍相对误差 <1e-3 |
| **P3** | 训练：几何改造 + 4 卡 FM 训练 | 4 卡 | 1 周 | **G3**：M=1 在**留出 seeds** 上 ≥ π0\* − 2 pp |
| **P4** | SDN 接入 + 分层评测 | 单卡 | 1 周 | **G4/G5**：`1.md` §7.1 的五道闸门 |
| — | **合计** | | **≈3.5–4 周 + 4 卡** | 任一门不过即回退（见 §8） |

**四条不可省的硬约束**（每条都有对应的失败模式，详见 §1.2）：

1. teacher 必须是 **vanilla π0\***，不是 π0\*+SDN；
2. 成功轨迹必须**按 `first_success` 截断**（SIMPLER 不会因成功提前终止）；
3. 采数与评测的 **seeds 必须不相交**；
4. 必须接受**单相机**，用 `empty_cameras=2` 补位。

## 1. 方案骨架

### 1.1 数据流

```
        [sdn 环境：py3.10 / torch2.3.1]              [flashvla 环境：py3.12 / torch2.9.1]
π0*  ──rollout──▶ raw episodes ──筛选/截断──▶ LeRobot ──监督FM──▶ pi05-flashvla ──▶ M=1 闸门 ──▶ +SDN
vanilla          (npz/h5 per ep)              (数据集)          (训练)            (闭环评测)      (方案2)
   │                 │                            │                  │                  │
 G0 定 teacher    G1 数据体检                  G2 格式/统计量      G3 基线不掉点      G4/G5 增益
```

**关键点：采集与训练在时间上解耦，因此不需要**把 SIMPLER 与 FlashVLA 装进同一个 Python 进程。
`2.md` §6.1 的 B0-1（环境门）在**数据路径上被摘掉**；但**评测路径仍需它**（§6）。

### 1.2 四条硬约束及其失败模式

| # | 约束 | 若违反 | 依据 |
| :- | :--- | :--- | :--- |
| 1 | teacher = `--method vanilla` | 用 `--method sdn` 采数会把 SDN 的选优结果**烘焙进权重**，FlashVLA 基线虚高，后续 SDN 增益无法归因 | `2.md` §6.5 风险 2、§7.4 |
| 2 | 按 `first_success` 截断 | 环境只在 `truncated`（TimeLimit）退出，`success` 不参与循环控制 → 成功后的几十步「任务已完成还在动」被当正样本 | `evaluate.py:210`、`:252-257`；`results.md` §5 实测 steps 恒等于 horizon |
| 3 | 采数 seeds 与评测 seeds 不相交 | 在训练用过的场景上评测 = 背题；且 `evaluate.py:99` 的 seeds 固定是 `range(n_trajs)` | `results.md` §10.3「选择集泄漏」 |
| 4 | 接受单相机 + `empty_cameras=2` | google 只有 `overhead_camera`、widowx 只有 `3rd_view_camera`，π0.5/FlashVLA 按 2–3 视角设计 | `evaluate.py:43-51`、`defaults.py:350-362` |

### 1.3 关键决策登记（训练侧配置）

| 项 | 取值 | 理由 |
| :--- | :--- | :--- |
| 学生 | `type: pi05-flashvla`，`pretrained_path: lerobot/pi05_base` | 官方 LIBERO 配方同源，超参与 FSDP 都已调好（`train/configs/pi05/libero/pi05_flashvla.yaml:2-9`） |
| `num_buffer_slots` N | **4** | `2.md` §7.3①：冷启动 hold-pose = N × act_steps，N=10 在 60 步任务上不可接受 |
| `chunk_size` C | **4** | 对齐 π0\* 的 `horizon_steps=4`；C=10 会让窗口跨 13 s（3 Hz），远超 widowx 的 60 步总量 |
| `n_action_steps` | **4** | 短 horizon 任务的硬约束 |
| `state_cond` | **`true`** | π0\* 是连续 7 维 proprio；离散 256-bin 进 prompt 会让精细任务掉点（`2.md` §7.3③） |
| `empty_cameras` | **2** | 单相机 + 两个 mask=0 的空位（`modeling_pi05.py:1224-1252`） |
| `normalization_mapping` | STATE/ACTION = `MEAN_STD` | 与 LIBERO 配方一致；统计量必须**由本数据集重算** |

## 2. 阶段 P0：teacher 判定（0.5 天，单卡）

**目标**：用最小代价判定「π0\* 是否真的不可替代」。这一门能整段作废后续跨架构设计。

**做什么**：
1. 在 py3.10 环境里跑 `lerobot/pi05_base` 零样本，9 任务 × 5 ep：

   ```bash
   # 需要一个 py3.10 的可跑 SIMPLER 环境（见 §6.1 的两种做法之一）
   for t in <9 tasks>; do python -m <simpler_eval> --policy pi05_base --task $t --n-episodes 5 --start-seed 100; done
   ```

2. 同一批 seeds 上跑一次 π0\* 的 `vanilla` 5 ep，作为同环境锚。

**产出**：一张 9×2 的表（`pi05_base` 零样本 vs π0\* vanilla）。

**验收 G0**：
- **若 `pi05_base` 零样本 macro ≥ 25%** → teacher 可直接换 pi05，**跨架构蒸馏这一层消失**，后续按同一流程但 teacher = pi05；
- **若 < 10%（预期）** → 按本方案走 π0\* 起手，不再讨论。

> 为什么预期很低：`pi05_base` 是通用基座，未做 SIMPLER 域微调；而 π0\* 的 `bridge_beta`/`fractal_beta`
> 是域内权重并已实测 67.3 / 68.7%。这也是 `2.md` §8.2 里唯一能把这条判断一票定性的实验。

**失败处理**：若环境搭不起来（sapien 2.2.2 + torch 2.9.1 冲突），P0 降级为「先做 P1，用 G3 反向验证」——
代价是多花 12 h 采数与 1 周训练，属可接受的最坏情况。

### 2.1 P0 实测结果（2026-11-20，GPU4，已执行）

> 实现细节、七个坑的解法、完整复现命令见同目录 `3_0.md`。

本地**没有** `lerobot/pi05_base`，只有 `ckpt/pi05_libero`（`pepijn223/pi05_libero_31_9_non_q`，
LIBERO 域微调版）。它不是基座而是**更强**的对照：若连域内微调过的 pi0.5 都跑不动，
未微调的 `pi05_base` 不可能更好。因此 P0 直接用它，**结论方向比原设计更严**。

环境冲突按 §6.1 的「跨进程 server」解决（已实现，见 §2.2）：
`flashvla` 环境（py3.12/torch2.9.1/lerobot0.5.1）加载权重并 serve，`sdn` 环境（py3.10/sapien2.2.2）
跑 SIMPLER 主循环，两者仅经 TCP 交换 `(image, state, instruction) → delta action`。

| 任务 | 成功/总数 | 成功率 |
| :--- | :--- | ---: |
| google_robot_close_drawer | 0/5 | 0.0% |
| google_robot_move_near | 0/5 | 0.0% |
| google_robot_open_drawer | 0/5 | 0.0% |
| google_robot_pick_coke_can | 0/5 | 0.0% |
| google_robot_place_apple_in_closed_top_drawer | 0/5 | 0.0% |
| widowx_carrot_on_plate | 0/5 | 0.0% |
| widowx_put_eggplant_in_basket | 0/5 | 0.0% |
| widowx_spoon_on_towel | 0/5 | 0.0% |
| widowx_stack_cube | 0/5 | 0.0% |
| **合计** | **0/45** | **0.0%** |

口径：seeds 100-104（与 R1 的 0-49 不相交）；每 4 个环境步重新观测一次（对齐 π0\* 的 `act_steps=4`）；
不因成功提前终止（与 `results.md` 一致）；单查询延迟 **376–418 ms**；21–55 s/episode。

**失败不是管线 bug**（这是关键区分）：单 episode 诊断显示
`action_std`(xyz) = 0.19/0.21/0.20、gripper 出现 13 个不同值、EEF 累计位移 **0.68 m** ——
策略在正常响应观测，机械臂在动，只是动得不对。

**失败的主要归因是动作尺度失配**（［已核实］读两侧统计量）：

| 维度 | LIBERO ckpt 的 `action.std` | fractal（Google Robot） | bridge（WidowX） |
| :--- | ---: | ---: | ---: |
| dx | 0.336 | 0.069 | 0.0096 |
| dy | 0.378 | 0.060 | 0.0135 |
| dz | 0.445 | 0.074 | 0.0125 |

即 pi05 输出的 delta 幅度是 SIMPLER 的 **5–30 倍**。为此补跑了一次「公平重标定」对照：
把输出先还原到 LIBERO 归一化空间，再用 SIMPLER 的逐维 `mean/std` 前推
（等价于 π0\* 用 SIMPLER 统计量反归一化）。重标定后 `pick_coke_can` 的平移幅度从
0.15/0.15/0.24 降到 **0.035/0.035/0.046**（进入合理量级），**但结果仍是 0/5**。

**G0 判定：不通过（按 <10% 口径）**，teacher 必须是 π0\*，跨架构自举这条路成立。
重标定后仍 0% 说明差距不只是尺度，而是视觉域、机器人形态与任务定义的整体失配 ——
这也意味着「换统计量就能救 pi05」的侥幸不成立。

> 局限（诚实记录）：只跑 5 ep/任务，0/45 的 95% 上界约 8%；且用了**重复视角**（单相机复制给
> 第二个视角槽）这一乐观设置，以及 `state` clip 到 [-1,1]。若换成「空白第二视角」，结果只会更差。

### 2.2 P0 的附带产出：评测基础设施（可直接复用到 G3）

`scripts/p0/` 下的两段代码把 §6.1 里「跨进程 server（1–2 天）」**提前做掉了一半**：

| 文件 | 作用 |
| :--- | :--- |
| `scripts/p0/pi05_server.py` | 在 `flashvla` 环境加载任意 FlashVLA/pi05 ckpt，TCP serve；支持 `--exec-steps`、`--clip-state`、`--rescale-stats`（跨域统计量重标定） |
| `scripts/p0/simpler_client_eval.py` | 在 `sdn` 环境跑 SIMPLER 主循环（reset / step / success / first_success 口径与 `evaluate.py:188-262` 一致），支持 `--start-seed`、`--debug-actions` |

两个必须记住的坑（都已在代码里注释）：
1. **numpy pickle 不跨版本**：`sdn` 是 numpy 1.24、`flashvla` 是 numpy 2.x，`numpy._core` 与
   `numpy.core` 路径不同 → 协议里只能传 `bytes` / `list` / `str` 这类纯 Python 对象。
2. **必须 `HF_HUB_OFFLINE=1`**：无网环境下 `TokenzierProcessorStep` 会去 HF 拉
   `google/paligemma-3b-pt-224`，本地有缓存也必须显式离线。

G3（M=1 闸门）与 P4 的正式评测可以直接复用这两段，只需把 server 换成 FlashVLA ckpt 并支持
`predict_action_chunk` 的 overlap 调度。

## 3. 阶段 P1：采数（1 天工程 + 12 h 算力）

### 3.1 改三处代码（约 120 行）

**① dump 钩子**：`third_party/SDN/policy/pizero/evaluate.py:188-262`

现成可用的变量（零额外推理开销）：

```210:233:third_party/SDN/policy/pizero/evaluate.py
        while not (predicted_terminated or truncated):
            proprio = obs['agent']['eef_pos']
            ...
            for action in actions:
                obs, reward, success, truncated, info = env.step(
                    np.concatenate([action["world_vector"], action["rot_axangle"], action["gripper"]]))
```

- `policy.step()` 的第一个返回值（raw chunk `[4,7]`）当前被 `_` 丢弃（`:213-221`）→ **接住**；
- 每步记录：`image`（**原始 640×512 / 640×480**，不要提前 resize）、`proprio`（8 维 raw，**反归一化前**）、
  `action`（7 维，已反归一化的 delta）、`instruction`（每步可能随子任务变化，`:243-245`）、`info['success']`；
- 每 episode 落一个 `npz`（图像用 mp4 另存可省 10× 空间），目录沿用 `result_dir`（`:311-318`）。

**② 加 `--start-seed`**：`evaluate.py:99` 现在是 `self.seeds = list(range(n_trajs))`，

**③ 一条断言**：落盘的 `action` 必须与 `env.step` 实际收到的 7 维向量逐位相同（`:226-227` 的 `np.concatenate`）。
这是整条管线最容易静默错位的地方（归一化/反归一化在两处发生，见 `simpler_adapter.py:82-95,111-131`）。

**不要用** ManiSkill 的 `RecordEpisode`（`third_party/ManiSkill2_real2sim/.../record.py:77-180`）：

### 3.2 跑一遍 vanilla（按任务定 episode 数）

```bash
cd third_party/SDN && conda activate sdn
export CUDA_VISIBLE_DEVICES=4
# 默认 50/任务 ≈ 2.5–3 h；这里建议非均匀加量（见下）
```

**为什么必须加量**：`results.md` §2 的实测成功率 × `first_success` 均值 → 50 ep/任务只产出
**≈303 条成功轨迹 / ≈1.1 万帧**；而 LIBERO 配方是 `50000 step × batch 32 = 160 万样本`（`pi05_flashvla.yaml:23-25`）。
1.1 万帧只有其 1/145，做 BC 等于背 34 条/任务。

**建议非均匀配额**（总量 ≈12 h）：

| 任务 | 成功率 | N_TRAJS | 预计成功条数 |
| :--- | ---: | ---: | ---: |
| `place_apple_in_closed_top_drawer` | ~20% | **500** | ~100 |
| `google_robot_open_drawer` | ~48% | **500** | ~240 |
| `widowx_carrot_on_plate` | ~56% | 300 | ~170 |
| `move_near` / `close_drawer` | 72–78% | 200 | 145–156 |
| 其余 4 个（coke_can / eggplant / spoon / stack_cube） | 76–88% | 150 | 115–130 |
| **合计** | | | **≈1200 条 / ≈4 万帧** |

**不要在采数时只存成功的**：失败轨迹的存储成本可忽略（<1 GB），但后续要拿它做
「混 10–20% 失败/未截断轨迹」的抗漂移增广（§5.3），重跑一遍要再花 12 h。

### 3.3 验收 G1（数据体检，1 小时）

写一个 `check_raw.py`，断言：

| 检查 | 阈值 |
| :--- | :--- |
| 每任务成功条数 | ≥ 50（`apple`/`open_drawer` 允许 ≥ 30 但需在报告中标注） |

## 4. 阶段 P2：数据工程（2 天，不占卡）

### 4.1 截断 + 筛选（半天）

对每个 episode：
- 只保留 `first_success != -1` 的；
- **切到 `first_success + k`（k = 0 或 2）**，尾部丢弃。`first_success` 现成有（`eval_utils.py:46-56`）；
- 保留 `episode_id / task / robot_type / seed` 元数据，供后续做留出集与分层统计。

### 4.2 转 LeRobot（1 天）

仿 `sim_eval/robotwin/robotwin_pipeline/scripts/convert_robotwin_to_lerobot.py:59-114`：

```python
features = {
    "observation.state": {"dtype": "float32", "shape": (8,),
                          "names": {"motors": ["x","y","z","qw","qx","qy","qz","gripper"]}},
    "action": {"dtype": "float32", "shape": (7,),
               "names": {"motors": ["dx","dy","dz","rx","ry","rz","gripper"]}},
    "observation.images.overhead_camera": {"dtype": "video", "shape": (512, 640, 3),
                                           "names": ["height", "width", "rgb"]},
}
ds = LeRobotDataset.create(repo_id=f"simpler/{task}", fps=3, features=features,
                           root=out_path, robot_type="google_robot", use_videos=True)
```

**两个必须处理的坑**：

1. **fps 不统一**：google_robot 是 `control_freq=3`（`custom_scenes/grasp_single_in_scene.py:70`、
   `open_drawer_in_scene.py:44`、`move_near_in_scene.py:64`），widowx 是 `5`（`put_on_in_scene.py:167`）。
   而 `MultiFlashVLADataset._MultiDatasetMeta` 会因 fps 不一致直接 `raise`
   （`flashvla/datasets/flashvla_dataset.py:150-151`）→ **建两个顶层数据集（fractal 3 Hz / bridge 5 Hz）**，
   或用 `robotwin_multitask.roots` 把同 fps 的叶子拼在一起（`:238-321`）。
2. **归一化统计量必须重算**：不能用 π0\* 的 `fractal_statistics.json` / `bridge_statistics.json`
   （那是它们自己的 p01/p99），本数据集用 `MEAN_STD` 走 LeRobot 自带的 `stats`。

### 4.3 验收 G2（格式与统计量对拍，半天）

| 检查 | 判据 |
| :--- | :--- |
| `FlashVLADataset.__getitem__` | 返回 `action.shape == [N·H, 7] = [16, 7]`，`action_is_pad` 只在尾部为 True |
| 窗口不跨 episode | 每条 episode 的最后 N·C 帧被正确 pad（`flashvla_dataset.py:108-122`） |
| stats 复算 | 用数据集自带的 `stats` 归一化后，`action / state` 的均值 ≈0、方差 ≈1（相对误差 <1e-3） |
| 动作连续性 | `|a_{t+1} − a_t|` 的 p99 不应出现孤立尖峰（截断边界除外） |
| 抽检 | 随机 10 条 episode 导出 gif + action 曲线，人眼确认「图-动」对齐 |

## 5. 阶段 P3：训练（1 周，≥2 卡，实用 4 卡）

### 5.1 配置

复制 `train/configs/pi05/libero/pi05_flashvla.yaml` → `train/configs/pi05/simpler/pi05_flashvla.yaml`，改动：

```yaml
policy:
  type: pi05-flashvla
  pretrained_path: lerobot/pi05_base
  num_buffer_slots: 4      # 原 4，不变
  chunk_size: 4            # 原 10
  n_action_steps: 4        # 原 10
  state_cond: true         # 原 false
  empty_cameras: 2         # 新增
dataset:
  repo_id: simpler/fractal  # 3 Hz 组；bridge 组另起一个 config
batch_size: 8
grad_accum_steps: 4        # 全局 32
steps: 12000               # 4 万帧 / 32 ≈ 1250 step/epoch → ≈10 epoch
```

`n_action_steps=4` 与 `chunk_size=4` 必须相等，否则 crossfade 逻辑会取不到第二块。
2 卡以上走 FSDP2（`fsdp.enable: true`，模板见 `train/configs/pi05/robotwin/pi05_flashvla.yaml:40-47`）。

### 5.2 训练

```bash
bash train/train.sh train/configs/pi05/simpler/pi05_flashvla.yaml 4   # accelerate --multi_gpu
```

**单卡不可行**：3B 全参 AdamW 的 fp32 master + 两个 moment ≈36 GB，加 bf16 权重 6 GB 与激活就超 46 GB
（L40S）。≥2 卡 FSDP2 是最低要求。

### 5.3 抗漂移增广（可选但便宜）

训练集里混入 10–20% 的**失败轨迹或不截断轨迹**（P1 已全量保存，无需重跑）。
理由：成功轨迹是 filtered BC，只覆盖 π0\* 访问过的状态分布，部署漂移出去后没有「救回来」的样本
（`2.md` §7.2 风险）。

### 5.4 验收 G3（决定性闸门）

| 检查 | 判据 |
| :--- | :--- |
| 离线 | 留出 seeds 上的验证集动作 L1 明显低于初始化（否则训练没学会，不用去评测） |
| **闭环 M=1** | **留出 seeds（如 100-149）9 任务 × 50 ep，macro ≥ π0\* 基线 − 2 pp** |
| 不「磨」 | 成功 episode 的 `first_success` 均值不超过 π0\* 的 1.5×（防「动得慢所以平滑」的假好） |
| 延迟 | `profile=True` 三段占比与 LIBERO ckpt 同量级 |

**G3 不过即停止**：说明 4 万帧 + 单相机撑不住，「同一基线」前提破裂，后续 SDN 增益无法归因。
此时按 §8 回退，**不要**继续做 P4。

## 6. 阶段 P4：SDN 接入与评测（1 周）

### 6.1 先解决评测环境（这是唯一没被摘掉的门）

SIMPLER 需要 py3.10 + sapien 2.2.2（`sdn/env_sdn.txt:114,126`），FlashVLA 需要 py3.12 + torch 2.9.1
（`environment.yml:5-12`）。两条路：

| 方案 | 做法 | 成本 | 限制 |
| :--- | :--- | :--- | :--- |
| **跨进程 server**（先做） | FlashVLA 侧起 policy server（仿 `sim_eval/robotwin/` 的 server/client 拆分），sdn 侧把 `policy.step` 换成 socket client | 1–2 天 | overlap/延迟计时失效；**但 M=1 闸门与增益对比都不需要计时** |
| **py3.10 统一环境**（复现用） | 新建 `environment_simpler.yml`：py3.10 + torch2.9.1 + lerobot0.5.1 + sapien2.2.2 + `sim_eval/simpler/` | 3–5 天 | `2.md` §6.2 的路线；只跑 vanilla FlashVLA 时**不需要** GroundingDINO，`transformers 4.44.2 vs 5.3.0` 死锁自动消失 |

推荐：**G3 用跨进程 server 先过闸门，P4 的正式数字再用统一环境重跑。**

### 6.2 接入 SDN（2–3 天）

- 机制与成本见 `1.md`；落点是 `modeling_pi05_flashvla.py` 的 `denoise_step`，M>1 时把
  `build_attention_mask_and_position_ids` 换成 `_build_shared_obs_mask(..., num_offsets=M)`（`1.md` §2.1）；
- 打分器可先复用已有的读出侧选择器 `flashvla/policies/pi05/sdn_selector.py:1-10`（R3 版本），
  再按 `1.md` §3.1/§3.2 换成配对 Δv + 接缝项 + 滞回。

### 6.3 验收 G4/G5

直接采用 `1.md` §7.1 的五道闸门：

| 闸门 | 判据 |
| :--- | :--- |
| G1 正确性 | M=1 逐位等于基线；M>1 每条流水线 == 独立跑 M 次 |
| G2 动力学 | 选择前后 `action_buffer` 逐位不变 |
| G3 成本 | `profile=True` 的 `action` 段 M/B 比；M=4 >1.8× 就降 M |
| G4 信号 | 离线候选排名与 GT 误差的相关度（`1.md` §7.1） |
| G5 效果 | 对照臂全开：随机选 / medoid / matched-compute / 只留 Stage1 或 Stage2 |

## 8. 风险与止损

| # | 风险 | 概率 | 后果 | 止损动作 |
| :- | :--- | :--- | :--- | :--- |
| 1 | 数据量/多样性不足 → G3 掉 >2 pp | **高** | 「同一基线」前提破裂 | 先加到 500/任务重采（+12 h），仍不过则回退路线 A |
| 2 | 单相机导致精细任务崩（`apple` / `stack_cube` / `carrot`） | **高** | 9 任务 macro 被拖低 | 按任务分层报数；必要时只在这些任务上保留 π0\* |
| 3 | 成功筛选固化错误（filtered BC 漂移） | 中 | 闭环首达步数暴涨 | §5.3 的失败轨迹混入 + 动作噪声增广 |
| 4 | 训练集/评测集 seeds 泄漏 | 中 | 数字虚高且不可复现 | §3.1② 的 `--start-seed`，写进 checklist |
| 5 | 评测环境迟迟装不干净 | 中 | P4 停滞 | 跨进程 server 兜底（overlap 论证降级，M=1 闸门不受影响） |
| 6 | 归一化统计量不一致 | 中 | 数字齐全但都是噪声 | G2 的对拍检查（相对误差 <1e-3） |
| 7 | 训练吞吐不达预期 | 低 | 时间 ×2 | 先跑 500 step 量一次 step/s 再定 `steps`［待核实］ |

**总止损点**：G3。过不了就退 `2.md` §5 的路线 A（双环境：SIMPLER 论证机制 + LIBERO 论证流式，1–2 周单卡）。
G3 过了之后，P4 失败只影响「SDN 增益」这一条结论，不影响「流式策略可在 SIMPLER 上训练」这一条。
