# SDN × FlashVLA：路线决策与可行性结论（2026-11-20 讨论汇总）

> 本文汇总三个问题的讨论结论：**SDN 要不要先验证、走哪条路线、用 π0\* 能否训出 FlashVLA**。
> 定位为决策层文档，位于 `sdn.md`（机制分析）、`sdn/sdnrun.md`（R3 落地）、
> `sdn/sdn_r1_env.md` / `sdn/sdn_r1_result.md`（R1 环境）、`sdn/results.md`（R1 结果）之上。
>
> 代码引用格式 `起始行:结束行:文件路径`，路径相对 `flashvla/` 仓库根。
> 标注约定：**［已核实］**= 实际读过代码 / 权重 / 日志；**［待核实］**= 需联网或跑实验确认。

## 0. TL;DR

| 问题                                        | 结论                                                                                                                                                                                                     |
| :------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 要不要先验证 π0.5+SDN（R3）再上 FlashVLA？ | **不需要，作为前置是错的**。R3 跑在 clean LIBERO 上，结构上呈现不出 grounding 增益，也测不到接缝与 overlap。价值降级为「滞后的同环境非流式锚」+「打分器开发台」                                    |
| 真正缺的前置是什么？                        | **SIMPLER 上的 4 个臂**：`vanilla`、`sdn_grounding`、`sdn_smooth`、`vanilla_perturbed(random_zeros_bbox)`。一个都没跑，`results.md` §7.1 已自认缺 vanilla                               |
| FlashVLA 能不能进 SDN 的环境（路线 B）？    | 能，但**卡点不在 SDN，在环境与权重**：`sim_eval/` 无 SIMPLER、`ckpt/` 无 SIMPLER 域 FlashVLA 权重、无 Bridge/Fractal 的 LeRobot 数据                                                           |
| 能不能直接用已有的 π0\* 训练 FlashVLA？    | **能，是路线 B 里最省的一条**：不是把 π0\* 装进 flashvla，而是「π0\* 当数据源/教师 → flashvla 的 pi05 架构训流式策略 → 与 π0\* 同环境配对」。代价是多卡训练 + 一个 py3.10 的 SIMPLER 评测环境 |
| 下一步？                                    | ① 补 SIMPLER `vanilla` 对照（2.5–3 h）；② FlashVLA 三段 profile（半天，可一票否决方案 2）；③ 查 Bridge/Fractal 的 LeRobot 数据可得性（1 天，决定路线 B 形态）                                      |

## 1. 目标与口径澄清

**最终目的**（用户明确）：

1. 在 **SDN 论文自己的环境（SIMPLER：5 Google Robot + 4 WidowX）** 中，呈现并评测 SDN 带来的
   **基于目标定位（Stage 1 grounding）** 与 **基于动作平稳性（Stage 2 smoothness）** 两类增益；
2. 使**同一机制在 FlashVLA 的流式推理中生效**（`sdn.md` 方案 2：M 条并行流水线，各采不同初始噪声）。

这一条纠正了早期把「π0.5+LIBERO（R3）」当作效果验证的定位。R3 仍然有用，但**不在关键路径上**。

## 3. R3（π0.5 + LIBERO）的定位

### 3.1 能做与不能做

| 用途                                       | 能否          | 原因                                                                              |
| :----------------------------------------- | :------------ | :-------------------------------------------------------------------------------- |
| 呈现「基于目标定位」的增益                 | ❌            | clean LIBERO 物体永远在位、无可破伪相关；object/spatial 基线已 97–98%            |
| 呈现「基于动作平稳性」的增益幅度           | ⚠ 只能给方向 | 50 ep 的 95% CI 半宽 ±2–3.4 pp                                                  |
| 测「接缝跳变」/「overlap 窗口」            | ❌            | 非流式，无跨 chunk 选择、无 env.step 重叠                                         |
| 打分器 / 负观测的**廉价消融台**      | ✅            | 换臂只是换环境变量；在 FlashVLA 里则是实现工作量                                  |
| 「流式没毁信号」的**同环境非流式锚** | ✅            | 当 FlashVLA+SDN 在 LIBERO 无增益时，用它区分「流式毁了」还是「LIBERO 本来无信号」 |

## 5. 路线 A vs 路线 B

|          | **路线 A：双环境**（推荐）    | **路线 B：统一到 SIMPLER**   |
| :------- | :---------------------------------- | :--------------------------------- |
| 机制论证 | SIMPLER / π0\*（R1 + 补 4 臂）     | SIMPLER / FlashVLA                 |
| 流式论证 | LIBERO / FlashVLA                   | 同左（单环境）                     |
| 论文结构 | 机制与流式分开论证，limitation 明确 | 单环境单 backbone 家族，叙事最干净 |
| 成本     | **1–2 周 + 单卡**            | **5–9 周 + 多卡训练**       |
| 主要风险 | 「两个环境不能直接比」被质疑        | 数据 / 权重 / 环境三处可能任一不过 |

路线 A 的 2×2 表（R3 只填右上角一格）：

|                    | 无 SDN                                | +SDN                                  |
| :----------------- | :------------------------------------ | :------------------------------------ |
| **π0.5**    | `results_pi05_baseline/ov0`（已有） | **R3**（代码已通，未跑；4.5 h） |
| **FlashVLA** | `results/ov1`（已有）               | 方案 2（M 条流水线）                  |

**路线 A 的诚实表述**：LIBERO 上做流式演示，只报「机制可搬进流式、成本可控、G1/G2 不破」是安全的；
要报 grounding 增益，必须把 LIBERO 扰动化（LIBERO-Plus 的背景/物体位移维度），否则就是 `sdn.md` §8 风险 7 说的「白跑算力」。

## 6. 路线 B 详细方案

### 6.1 B0：三道门（1–2 天，不占卡，先做）

| 门                                                  | 现状                                    | 若不通过                                |
| :-------------------------------------------------- | :-------------------------------------- | :-------------------------------------- |
| **B0-1 环境**：SIMPLER 与 FlashVLA 同进程     | 不同 py 版本，§6.2 有解                | 退跨进程 server，overlap 论证失效       |
| **B0-2 权重**：SIMPLER 域 FlashVLA            | 没有；需自造（§6.3 / §7）             | 路线 B 关闭                             |
| **B0-3 数据**：Bridge/Fractal 的 LeRobot 格式 | 本地没有；［待核实］HF 是否有现成转换版 | 退化到「π0\* 自举数据」（§7）或路线 A |

### 6.2 环境：把 FlashVLA 降到 py3.10，而不是把 SIMPLER 升到 py3.12

| 方向                         | 障碍                                                                                                 | 判断              |
| :--------------------------- | :--------------------------------------------------------------------------------------------------- | :---------------- |
| SIMPLER → py3.12            | sapien 2.2.2 无 cp312 wheel；`mani_skill2_real2sim` 依赖 sapien 2.x API                            | ❌ 风险高         |
| **FlashVLA → py3.10** | torch 2.9.1 有 cp310 wheel；lerobot 0.5.1 支持 3.10；代码通篇 `from __future__ import annotations` | ✅ **推荐** |

新建 `environment_simpler.yml` = py3.10 + torch2.9.1+cu128 + lerobot0.5.1 + sapien2.2.2 + mani_skill2_real2sim

+ `tf>=2.16` + `vulkan-loader`，复用 `sdn_r1_result.md` §2 的 5 条踩坑修正。

**`transformers` 冲突的唯一正解**：R1 的 `sdn` 环境固定 `4.44.2`（为 `groundingdino==0.1.0`），FlashVLA 需 `5.3.0`。
→ **不要共存**：Stage 1 改用 transformers 自带的 `GroundingDinoForObjectDetection`（权重已是标准格式）+ SAM2，
再用 R1 已产出的 450 episode 的 bbox 做 IoU / 面积分布对拍，确认掩码等价后再用于实验。

**新目录**：`sim_eval/simpler/`（仿 `sim_eval/libero/` 写 `eval.py` + `eval.sh`，保留 `GPUS` 语义，避免 `CUDA_VISIBLE_DEVICES` 被覆盖的坑）。
**验收**：π0\* 在 `widowx_stack_cube` 上跑 2 episode 跑通，`Time/Step` 与 R1 的 0.55 s/step 同量级。

## 7. 能不能用已有的 π0\* 训练 FlashVLA？

**结论：能，且是路线 B 里最可行的一条。** 但不是「把 π0 装进 flashvla 直接训」，而是
「π0\* 出数据 / 当教师 → flashvla 的 pi05 架构训流式策略 → 与 π0\* 做同环境配对」。

### 7.1 权重结构核实（决定性事实）

拆开 `pretrained/open-pi-zero/bridge_beta_step19296_2024-12-26_22-30_42.pt`（938 个张量，mmap 读取）：

```
top-level: joint_model / action_encoder / action_decoder / proprio_encoder
           / vision_tower / embed_tokens / multi_modal_projector
joint_model.mixtures.vlm.layers.0.self_attn.q_proj   (2048, 2048)
joint_model.mixtures.vlm.layers.0.self_attn.k_proj   ( 256, 2048)   ← GQA
action_encoder: linear_1 (1024, 7) → linear_2 (1024, 2048) → linear_3 (1024, 1024)
action_decoder (7, 1024)      proprio_encoder (1024, 7)
```

对照 flashvla 的 pi05 期望（`flashvla/policies/loading.py:207-218` 的 `PI05_KEY_RULES`）：

| 项                   | π0\*                                                   | flashvla pi05                                                                                                                               | 能否直通                |
| :------------------- | :------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------ | :---------------------- |
| 层命名               | `joint_model.mixtures.{vlm,action,proprio}.layers.*`  | `paligemma_with_expert.{paligemma,gemma_expert}.*`                                                                                        | ❌ 需重写映射           |
| 隐藏维               | vlm 2048 / expert 1024                                  | PaliGemma 3B → 2048 / 1024                                                                                                                 | ✅ 形状一致             |
| action 投影          | `action_encoder` 三层 MLP（含 time 拼接）             | `suffix_embedder.action_in_proj + time_mlp_in/out`（`modeling_pi05.py:160-163`）                                                        | ✅ 语义等价             |
| **state 通路** | **独立第三路 `proprio` 流参与 joint attention** | 只有两路：`state_cond=False` 离散进 prompt / `state_cond=True` 走 adaRMS（`configuration_pi05.py:100`、`modeling_pi05.py:165-169`） | ❌ **结构缺一路** |

**两条推论：**

1. **不能「直接装载」**：这不是 rename，而是给 joint layer 补第三条 proprio 流（3–5 天）。
2. **装载了也只是初始化**：FlashVLA 的流式能力是**训练出来的**——训练时 `_build_per_chunk_time`
   让各槽在不同 t 上学单步欧拉（`modeling_pi05_flashvla.py:740-800` 中
   `x_t = t·noise + (1-t)·actions`、`u_t = noise - actions`），而 π0\* 是在 10 步 ODE 上训的，
   在 t=0.25 做单步会显著掉点。**训练这一步省不掉。**

### 7.2 三条做法

| 方案                          | 做法                                                                                                                                                       | 需要的数据                                  | 工程量                                    | 保真度                                         |
| :---------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------ | :---------------------------------------- | :--------------------------------------------- |
| **P1 自举数据（推荐）** | 给 pizero 的 rollout 加「录轨迹」开关，用 π0\* 在 9 任务上采 `(obs, state, action)` → 转 LeRobot 格式 → 用 `flashvla/train.py` 现有监督 FM 目标训练 | **不需要 Bridge/Fractal**，π0\* 自产 | 采数 0.5 天 + 转换 1–2 天 + 训练 1–2 周 | 学生学 π0\* 行为（DAgger 闭环），不引入新信息 |
| **P2 自蒸馏**           | teacher = π0\*（可给任意 `(o,x,t)` 的 v），student = buffer 结构；loss 改为匹配教师速度场                                                               | **只要观测**（连动作都不用存）        | 新写 forward，+3–5 天                    | 最保真（行为保持），代码为新增需自证           |
| **P3 权重移植**         | 把 π0\* 映射进 flashvla pi05（补 proprio 流）                                                                                                             | 仍需数据 / 教师                             | 3–5 天                                   | 只是初始化                                     |

**推荐 P1 起步，P3 只在需要「同 backbone 严格性」时做。**
P1 的已知风险：自举数据只覆盖 π0\* 访问到的状态分布，**错误会被固化**。缓解：混 10–20% 的扰动 rollout，或训练时加动作噪声增广。

### 7.3 训练前必须定的三件事

**① 几何（N = buffer 槽 = ODE 步数）**

| 项           | π0\*（SIMPLER）    | FlashVLA-LIBERO      | SIMPLER 建议        |
| :----------- | :------------------ | :------------------- | :------------------ |
| chunk        | `horizon_steps=4` | `chunk_size=10`    | **4**         |
| 执行步       | `act_steps=4`     | `n_action_steps=5` | **4**         |
| buffer N     | 10 步 ODE           | 4                    | **4–5**      |
| suffix token | —                  | 4×10 = 40           | 4×4 = **16** |

**必须接受的不利事实**：FlashVLA 每个 chunk 只收到 **N 次单步欧拉**，π0\* 是 10 步。
对齐 10 步就要 N=10，但冷启动是 `N × act_steps` 的 hold-pose：N=10 → **36 个控制步**，
在 `widowx_carrot_on_plate`（horizon 60）上等于整局 60% 在僵住，不可接受。
**所以 N 被短 horizon 逼到 4–5，质量缺口只能靠训练补**——这正是 FlashVLA 在 LIBERO 上做的事。

**② `long_horizon` 冲突**：SDN 的 Stage 2 在 `{4,5,10}` 的**延长 chunk** 上看更长运动；
流式下候选只有 `chunk_size=4` 一块，**`long_horizon` 天然被截断**。必须提前决定：
跨槽拼接看 8/16 步，还是接受 `lh ≤ 4` 并靠新增的**接缝项**补回信号。**不要等训练完再想。**

**③ state 通路**：π0\* 是连续 7 维喂 proprio 流。若学生用 `state_cond=False`（离散 256 bin 进 prompt），
精细任务（`carrot_on_plate`、`stack_cube`）会掉点。**建议 `state_cond=True`（adaRMS 连续状态）**。

### 7.4 验收闸门

**M=1 的 FlashVLA 在 9 任务上不低于 π0\* 基线 − 2 pp。** 过不了说明蒸馏伤了策略，
「同一基线」前提破裂，后续所有 SDN 增益都不可归因。

## 10. 三个原问题的一句话回答

1. **要不要先验证 π0.5+SDN？** 不需要。它跑在 clean LIBERO 上，测不到你要的 grounding 增益，也测不到接缝 / overlap；降级为「滞后的同环境非流式锚 + 打分器开发台」。
2. **直接走 FlashVLA+SDN？** 也不是「直接」：先补 SIMPLER 的四个臂、再做 FlashVLA 的三段剖面，然后才决定 M 与打分器形态。
3. **能否用已有 π0\* 训练 FlashVLA？** 能。π0\* 解决了「域内权重」与「域内数据来源」两个最贵的问题；剩下的是多卡训练 + 一个 py3.10 的 SIMPLER 评测环境，以及必须提前接受的 **N=4 单步欧拉 vs 10 步 ODE 的质量缺口**。
